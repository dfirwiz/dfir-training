학습 범위와 예제

둘째 날 14강 · 교재 인쇄 153~162쪽의 학습 주제를 자체 예제와 해설로 풀었습니다. 아래 주소·숫자·흐름은 별도 표시가 없으면 가상 학습 예시입니다. 명령은 분석 절차이며 실제 실행 출력으로 제시하지 않습니다.

1. IPv6는 숫자만 길어진 IPv4가 아닙니다

128비트 주소로 주소 공간이 커졌다는 점은 출발점입니다. 분석가는 여기에 더해 고정 크기 기본 헤더, 확장 헤더 연결, 브로드캐스트 대신 쓰는 멀티캐스트, ICMPv6의 역할을 배워야 합니다. 익숙한 IPv4 오프셋과 타입 번호를 그대로 대입하면 엉뚱한 값을 읽을 수 있습니다.

과거 교재의 IPv6 전환 시기 예측이나 특정 트래픽 점유율은 당시의 맥락입니다. 현재 환경을 설명하는 확정 수치로 사용하지 않습니다. IPv6를 쓴다는 이유만으로 암호화와 인증이 자동으로 보장되는 것도 아닙니다. 실제 보안 기능의 설정과 경로를 확인해야 합니다.

2. 주소는 여덟 묶음으로 펼쳐서 확인합니다

IPv6 주소는 16비트씩 여덟 묶음을 16진수로 적습니다. 각 묶음의 앞쪽 0을 줄일 수 있고, 연속된 0 묶음은 ::로 한 번 줄일 수 있습니다. 예를 들어 2001:0db8:0000:0000:0000:0000:0000:0025는 2001:db8::25로 표현할 수 있습니다. 주소가 달라진 것이 아니라 같은 값을 다르게 적은 것입니다.

::를 두 번 쓰면 가운데에 몇 묶음을 채울지 모호해집니다. 로그 비교에서는 문자열이 달라도 같은 주소인지 정규화한 값을 비교합니다. URL에서는 주소와 포트의 콜론이 헷갈리지 않도록 [2001:db8::25]:443처럼 대괄호로 주소를 묶습니다. 이 노트의 2001:db8::/32는 문서용 예시입니다.

주소의 범위도 봅니다. ::1은 루프백, fe80::/10은 링크 로컬 범위, ff00::/8은 멀티캐스트입니다. fc00::/7은 고유 로컬 주소 범위입니다. 교재의 “FE로 시작하면 링크 로컬”이라는 넓은 표현 대신 정확한 프리픽스를 확인합니다. 링크 로컬 주소는 인터페이스 범위와 함께 읽어야 하며 라우터 너머의 전역 목적지처럼 다루지 않습니다.

3. 기본 헤더 40바이트의 계산 기준

IPv4의 IHL은 옵션에 따라 달라지지만 IPv6 기본 헤더는 40바이트입니다. Payload Length는 이 기본 40바이트 뒤의 길이로, 확장 헤더와 상위 데이터를 포함합니다. 일반 패킷에서 값이 80이라면 기본 헤더를 더한 전체 IPv6 길이는 120바이트입니다. 곧바로 TCP 데이터가 80바이트라고 읽지 마세요.

Version, Traffic Class, Flow Label, Payload Length, Next Header, Hop Limit, 출발지 주소, 목적지 주소를 구별합니다. 출발지 주소는 기본 헤더 오프셋 8~23, 목적지는 24~39에 놓입니다. IPv4 TTL과 비슷한 역할을 Hop Limit이 담당하지만 필드 위치는 다릅니다.

IPv6 기본 헤더에는 IPv4 같은 헤더 체크섬이 없습니다. 그렇다고 오류 검출이 전혀 없다는 뜻은 아닙니다. 링크와 상위 프로토콜의 검사 역할을 함께 봅니다. TCP·UDP·ICMPv6의 가상 헤더 계산에는 IPv6 주소 등의 정보가 참여합니다.

4. Next Header를 따라가야 상위 프로토콜을 찾습니다

기본 헤더의 Next Header가 TCP를 바로 가리킬 수도 있고, 확장 헤더를 가리킬 수도 있습니다. 확장 헤더가 있으면 각 헤더의 다음 헤더와 길이 규칙을 따라 이동해야 합니다. IPv6 기본 헤더 뒤 40바이트 위치가 언제나 TCP 시작은 아닙니다.

예를 들어 기본 헤더 40바이트, 확장 헤더 8바이트, TCP 헤더 32바이트, 데이터 40바이트라는 가상 패킷을 보겠습니다. Payload Length는 8+32+40=80이고 전체 IPv6 길이는 120입니다. TCP 시작은 IPv6 시작에서 48바이트 위치입니다. 일반 IPv4 길이식을 그대로 대입하지 않는 이유입니다.

5. 라우터의 단편화와 종단의 단편화를 구별합니다

IPv6 라우터는 IPv4처럼 지나가는 패킷을 단편화하지 않습니다. 필요하면 Packet Too Big으로 알리고 송신자가 패킷 크기를 조정합니다. 송신 측 단편화에는 Fragment 확장 헤더가 사용됩니다. 이 때문에 ICMPv6를 전부 차단하면 크기에 따라 통신이 막히는 문제가 생길 수 있습니다.

IPv4와 IPv6를 함께 쓰는 환경에서는 어느 경로로 연결이 성공했는지도 기록합니다. 주소 변환·터널·프록시가 있으면 관측 위치마다 안팎 헤더가 달라질 수 있습니다. IPv4 정책만 확인하고 IPv6 경로까지 통제된다고 가정하지 마세요. 반대로 IPv6를 발견했다는 사실만으로 우회 공격이라고 결론내리지도 않습니다.

복습 · 조건을 바꾸어 생각하기

질문 1. Payload Length 100이면 기본 IPv6 패킷 길이는?

일반 조건에서 140바이트입니다. 기본 헤더 40은 Payload Length에 들어 있지 않습니다.

질문 2. IPv6 시작 40바이트 뒤를 항상 TCP로 읽어도 되나요?

확장 헤더가 있을 수 있습니다. Next Header 체인을 따라갑니다.

질문 3. fe로 시작하는 주소는 전부 링크 로컬인가요?

정확한 링크 로컬 프리픽스 fe80::/10에 속하는지 확인합니다.

질문 4. IPv6면 보안이 자동으로 보장되나요?

암호화·인증·필터링의 실제 설정과 경로를 별도로 확인해야 합니다.
