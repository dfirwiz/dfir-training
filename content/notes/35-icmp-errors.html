학습 범위와 예제

둘째 날 13강 · 교재 인쇄 142~152쪽의 학습 주제를 자체 예제와 해설로 풀었습니다. 아래 주소·숫자·흐름은 별도 표시가 없으면 가상 학습 예시입니다. 명령은 분석 절차이며 실제 실행 출력으로 제시하지 않습니다.

1. 반송 봉투 안에는 원래 보낸 봉투의 정보가 있습니다

라우터가 오류를 보낼 때 “안 됩니다” 한마디만 있으면 어느 통신의 문제인지 모릅니다. 그래서 ICMP 오류에는 원인이 된 원래 패킷의 일부가 들어갑니다. 바깥 IP 헤더는 오류 메시지의 전달 경로이고, 안쪽 IP 헤더는 실패한 원래 통신의 정보입니다. 같은 패킷 안의 두 주소 쌍을 따로 읽는 것이 핵심입니다.

전통적인 ICMPv4 오류 형식은 원래 IP 헤더와 그 뒤 최소 8바이트를 인용합니다. 실제로는 더 많은 내용을 포함하는 메시지도 있습니다. 인용 범위를 확인하면 원래 TCP·UDP 포트 또는 ICMP 식별자를 연결할 수 있지만, 짧거나 잘린 인용에 없는 필드를 억지로 해석하지 않습니다.

2. 시간 초과와 도달 불가의 세부 사유

Type 11 Code 0은 전달 중 TTL 소진, Code 1은 조각 재조립 시간 초과를 알립니다. 두 메시지는 같은 “시간 초과”라는 말이 있어도 원인이 다릅니다. 경로 추적의 정상 탐사에서 보이는 TTL 소진을 곧바로 장애나 공격으로 해석하지 마세요.

Type 3은 Destination Unreachable입니다. 네트워크·호스트·프로토콜·포트·정책 등 여러 세부 Code가 있습니다. 특히 Code 4는 IPv4에서 DF가 설정되어 단편화가 필요한 경우의 경로 MTU 탐색과 연결됩니다. 단순히 오류를 지우기 위해 전부 막으면 큰 데이터 전송의 문제 해결 신호를 잃을 수 있습니다.

ICMPv4 오류의 기본 구분
Type / Code뜻연결할 조사
11 / 0전달 중 TTL 초과탐사·라우팅 루프·경로
11 / 1조각 재조립 시간 초과조각 누락·시간·수신 조건

3. tcpdump와 표시 필터가 다른 개수를 낼 수 있습니다

가상 ICMP 오류의 바깥 주소는 공인 대역이고 인용된 원래 주소가 사설 대역이라고 합시다. BPF의 일반 host/net 조건은 기본 바깥 IP 헤더를 대상으로 할 수 있는 반면, Wireshark 표시 필터의 ip.addr는 해석된 여러 IP 주소 필드를 대상으로 매칭할 수 있습니다. 두 도구의 결과가 다르다고 한쪽이 무조건 틀린 것이 아닙니다.

이럴 때는 파일·시간·패킷 번호·필터 종류를 맞추고, 선택된 패킷의 바깥 주소와 안쪽 주소를 각각 기록합니다. 캡처 필터와 표시 필터의 문법·해석 계층 차이를 확인하는 연습입니다. 인용된 내부 주소가 밖으로 보인다면 정보 노출의 단서일 수 있지만 현재 내부 호스트가 직접 외부와 연결했다는 뜻으로 확대하지 않습니다.

4. 오류에 오류로 답하지 않는 이유

ICMP 오류에 다시 ICMP 오류를 보내면 서로 오류를 주고받는 고리가 생길 수 있습니다. 그래서 오류 메시지에 대한 오류 생성에는 제한이 있습니다. 브로드캐스트·멀티캐스트 대상과 비초기 IP 조각 등에도 오류 생성 제한이 적용됩니다. Echo Reply처럼 정보 응답과 ICMP 오류를 같은 것으로 묶어 외우지 마세요.

조각 재조립 시간 초과의 경우 초기 조각의 수신 여부도 고려합니다. 첫 조각이 없으면 원래 상위 통신을 식별할 정보가 부족할 수 있습니다. 메시지가 안 왔다고 재조립이 성공했다는 뜻은 아닙니다. 생성 금지 조건·속도 제한·정책·손실로 오류를 못 볼 수도 있습니다.

IPv6에는 별도의 ICMPv6 규칙과 예외가 있습니다. 예를 들어 Packet Too Big은 멀티캐스트 관련 예외를 포함하므로 IPv4 억제 표를 그대로 복사하면 안 됩니다. 필요한 제어 메시지는 유지하면서 메시지 종류와 정책을 구별하는 방식으로 검토합니다.

5. 오류를 서비스 지도와 연결할 때의 한계

여러 포트에 대한 Port Unreachable이 짧은 시간에 몰리면 탐사 가설을 세울 수 있습니다. 그러나 잘못된 설정의 응용도 비슷한 오류를 반복합니다. 대상을 얼마나 넓게 훑는지, 요청이 어떤 프로세스에서 나왔는지, 정상 업무 시각과 맞는지를 함께 봅니다.

보고서는 “11/0을 관측했다”, “인용 목적지가 이 주소였다” 같은 사실을 먼저 적고 라우팅 루프·탐사 등의 가설과 필요한 라우팅·방화벽·단말 자료를 이어 적습니다. 오류의 존재는 진단 단서이지 그 자체가 공격자의 의도를 증명하지는 않습니다.

복습 · 조건을 바꾸어 생각하기

질문 1. ICMP 안의 사설 주소가 보이면 그 호스트가 직접 보낸 ICMP인가요?

인용된 원래 패킷의 주소일 수 있습니다. 바깥 발신자와 분리해 읽습니다.

질문 2. 11/0과 11/1은 같은 원인인가요?

전달 중 TTL 소진과 조각 재조립 시간 초과로 다릅니다.

질문 3. ICMP 오류가 없으면 통신이 성공했나요?

생성 억제·필터·손실·수집 범위 때문에 안 보일 수 있어 성공의 증거가 아닙니다.
