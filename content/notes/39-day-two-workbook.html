학습 범위와 예제

둘째 날 17강 · 교재 인쇄 30~152쪽의 학습 주제를 자체 예제와 해설로 풀었습니다. 아래 주소·숫자·흐름은 별도 표시가 없으면 가상 학습 예시입니다. 명령은 분석 절차이며 실제 실행 출력으로 제시하지 않습니다.

1. 문제를 풀기 전에 무엇을 세는지 적습니다

이번 보충은 전자 워크북 둘째 날의 네 실습을 앞 강의와 연결하는 가이드입니다. 문제와 기재 해설을 확인하고, 제공된 여섯 PCAP 파일의 레코드와 주요 필드를 바이트 단위로 읽었습니다. Wireshark GUI·tcpdump·TShark를 실행한 결과나 당시 VM의 실제 수신 동작을 재현한 것으로 표시하지 않습니다.

파일 확장자가 .pcap이라고 실제 파일 형식이 항상 전통 PCAP인 것은 아닙니다. 제공 자료에는 PCAPNG 형식도 있었습니다. 파일 서명을 보고 형식을 판단한 뒤 레코드를 세었습니다. 전체 프레임 수, 필터로 선택한 패킷 수, 고유 포트 수, 연결 수는 서로 다른 단위입니다. 숫자를 적을 때 이 구별부터 붙여 보세요.

2. 표시 필터: 주소 방향과 내보낼 집합 확인

첫 실습은 주소·ARP·헤더 길이·DNS를 표시 조건으로 바꾸는 연습입니다. 출발지와 목적지를 OR로 연결해야 하는지, 한 방향만 필요한지 먼저 한국어로 씁니다. ARP 요청은 arp.opcode == 1처럼 프로토콜 내부 필드로 찾습니다. Ethernet 브로드캐스트만 고르면 ARP 이외의 트래픽도 섞일 수 있습니다. 제공 파일의 바이트 검사에서는 ARP 요청 16개를 확인했습니다.

IPv4 옵션이 있는 패킷은 헤더 길이부터 확인합니다. 첫 옵션의 타입을 찾는 문제라면 “옵션 전체 어디엔가 값이 있다”와 “첫 옵션이 그 값이다”를 구별합니다. 구조를 읽는 필터와 바이트 위치를 보는 필터가 같은 질문에 답하는지도 확인하세요. 비초기 조각이나 잘린 데이터는 따로 점검합니다.

DNS를 UDP로 한정하라는 질문에서는 단순 dns만으로 끝내지 않습니다. DNS는 TCP로도 전달될 수 있기 때문입니다. udp and dns로 후보를 고르고 요청·응답 및 해석 상태를 점검합니다. 표시된 패킷만 새 파일에 내보내고, 다시 열어 예상 개수·시간·바이트가 맞는지 확인합니다. 아래 제공 dns.pcap의 14개 레코드는 별도 파일의 검사값이며, 이번에 GUI 내보내기를 실행해서 새로 만든 결과는 아닙니다.

arp.opcode == 1
ip.hdr_len > 20
udp and dns

3. BPF: 플래그와 DNS 오프셋을 검산합니다

연결 시작은 목적지 포트를, 연결 시작 응답은 출발지 포트를 조사합니다. 제공 int-server 파일에서 플래그 바이트 정확 일치 0x02의 레코드는 13개였지만 고유 목적지 포트는 6개였습니다. 0x12의 레코드는 5개, 고유 출발지 포트는 3개였습니다. “패킷 수가 곧 서비스 수”가 아님을 보여주는 예입니다.

이 숫자는 해당 파일에 대한 정확 일치 조건의 결과입니다. 실제 조사에서는 앞 강의처럼 ECN을 허용하는 마스크와 비교하고 어떤 추가 플래그를 제외했는지 기록합니다. FIN 또는 RST 중 하나라도 찾는 조건은 & 0x05 != 0입니다. 목적지 포트 143에서 PSH·ACK가 모두 켜졌는지는 & 0x18 = 0x18로 비교합니다. 두 식의 != 0과 = 마스크 값을 바꾸어 쓰지 않습니다.

DNS 헤더는 UDP의 8바이트 뒤에서 시작합니다. 따라서 UDP 기준 오프셋 10은 DNS 플래그의 상위 바이트이고, QR은 그 바이트의 0x80 비트입니다. UDP 기준 오프셋 18의 두 바이트는 DNS ARCOUNT입니다. 질의이면서 추가 레코드가 있는 조건을 만들 때 QR=0과 ARCOUNT>0을 함께 검사합니다. 제공 dns 파일에서 이 바이트 조건에 해당한 레코드는 1·4·6·8입니다. 완전한 DNS 의미 검증과 가변 질문 이름의 파싱은 별도 단계입니다.

tcpdump -nn -r dns.pcap 'udp dst port 53 and (udp[10] & 0x80) = 0 and udp[18:2] > 0'

4. 마스크는 연속된 주소 범위만 고르지 않습니다

마지막 바이트에 (값 & 0xd0) = 0xd0을 적용하면 0xd0의 1인 자리, 즉 128·64·16 자리가 모두 켜져 있어야 합니다. 32 자리와 아래 네 자리는 검사하지 않으므로 두 구간이 선택됩니다. 208~223과 240~255입니다. 그 사이 224~239는 16 자리가 꺼져 있어 빠집니다.

총 선택 값은 32개입니다. 제공 추가 실습 파일은 끝 바이트 0~255를 비교하는 연습에 대응하며 레코드는 256개입니다. 이 마스크가 단일 CIDR 프리픽스와 언제나 같은 집합이라고 외우지 마세요. 검사하지 않는 자리가 중간에 있으면 여러 떨어진 구간이 될 수 있습니다.

5. TCP: 체크섬 오류와 겹치는 바이트를 별도로 봅니다

TCP 실습의 체크섬 질문에서는 IP 체크섬이 맞아도 TCP 체크섬이 틀릴 수 있음을 확인합니다. 제공 TCP 파일을 재계산했을 때 TCP 체크섬이 유효하지 않은 레코드는 121·128이었습니다. 그중 RST가 포함된 흐름에서는 RST를 보았다는 사실과 종단이 실제 종료했다는 판단을 분리합니다. 실제 수신 동작까지 확인하려면 종단 자료가 더 필요합니다.

같은 출발지 포트와 같은 SEQ 범위인데 내용이 다른 두 세그먼트는 단순한 동일 데이터 재전송과 다릅니다. 서로 다른 재조립 정책에서 어떤 바이트를 채택하는지가 달라질 수 있습니다. SYN 데이터도 함께 있을 수 있으므로 현재 기능·유효성·스트림 문맥을 확인합니다. 이 현상을 발견했다고 운영 서버에 공격을 재전송할 필요는 없습니다. 확보한 자료에서 범위와 내용을 비교하면 됩니다.

다른 문제의 여러 SYN은 포트·초기 SEQ·간격을 비교해 같은 시도의 재전송과 새로운 연결 후보를 구별합니다. 비정상 플래그 조합은 SYN/FIN/RST 등 각 의미가 상태에서 충돌하는지 보고, 단순히 모든 플래그가 있다는 이유만으로 실제 침해를 주장하지 않습니다. 외부 SYN/ACK만 보이는 사례는 반사 응답 가설과 수집 범위 가설을 나눕니다.

URG 추가 문제는 첫 세그먼트의 포인터가 그 세그먼트 데이터 바깥을 가리킬 수도 있음을 보여줍니다. 다음 세그먼트까지 바이트 위치를 이어서 계산하고, 응용이 어떤 바이트를 읽었는지는 워크북의 기재 결과와 현재 재현 결과를 구별합니다. 한 구현의 문자가 빠지는 동작을 모든 TCP의 보편 규칙으로 일반화하지 않습니다.

6. UDP·ICMP: 잘못된 응답도 학습 자료에 들어 있습니다

UDP·ICMP 실습에서는 브로드캐스트에 대한 오류, 비초기 조각 관련 오류, ICMP 오류에 대한 또 다른 오류를 검토합니다. 패킷 쌍이 존재한다고 그 관계가 표준상 올바르다는 뜻은 아닙니다. 앞 강의의 오류 생성 억제 조건을 적용해 “왜 이 응답이 없어야 하는가”를 설명해 보세요.

TTL이 단계적으로 커지는 Echo들과 Time Exceeded의 인용 원본을 연결하면 경로 탐사 가설을 검토할 수 있습니다. 운영체제는 도구 방식과 페이로드의 단서로 추정하되 확정하지 않습니다. 요청보다 응답이 많거나 적은 묶음은 ID·SEQ·주소·데이터·수집 조건을 다시 맞춥니다.

ICMP 데이터에서 명령과 결과처럼 보이는 내용이 이어지면 일반 도달성 점검 외의 사용을 의심할 수 있습니다. 하지만 프로그램 이름이나 공격자까지 패킷만으로 정하지 않습니다. 원래 프로세스, 업무 목적, 시간대와 종단 기록을 확인합니다. 추가 문제에서 Echo에 대한 “프로토콜 도달 불가”가 돌아오는 모순도 Type/Code와 원래 요청을 비교해 설명합니다.

7. 확인한 범위와 남은 실행 검증

여섯 파일 총 1067개 레코드의 프레이밍과 주요 헤더를 오프라인으로 읽었고, BPF 마스크의 0~255 값과 길이·ACK 예제를 계산했습니다. 이것은 저장된 바이트의 검산입니다. 실제 캡처 필터 엔진, Wireshark의 재조립 설정과 GUI 내보내기, 대상 운영체제의 수신·캐시·라우팅 동작을 실행 검증한 것과 구별합니다.

이 가이드의 필터를 직접 실행할 때는 설치 버전, 원본 해시, 사용 명령·설정, 선택 레코드 수를 기록하고 표본 패킷을 원본 바이트와 대조하세요. 결과가 다르면 숫자를 억지로 맞추지 말고 파일 버전·필터 의미·오프로딩·중첩 헤더·재조립 차이부터 점검합니다. 그 차이를 설명하는 과정이 실습의 목적입니다.

질문 1. SYN 13개면 서비스 13개인가요?

아닙니다. 같은 대상의 재시도가 포함될 수 있고, 제공 파일에서는 고유 목적지 포트가 6개였습니다.

질문 2. 마스크 0xd0 조건은 왜 두 구간인가요?

32 자리를 검사하지 않지만 16 자리는 1이어야 해서 208~223, 240~255가 선택됩니다.

질문 3. DNS 헤더 기준 10과 UDP 기준 10은 같나요?

아닙니다. UDP 헤더가 8바이트이므로 기준점을 명확히 적습니다.

질문 4. 이번 바이트 검산이 VM 실행 검증을 대신하나요?

저장 필드와 계산을 확인한 범위입니다. 수신 구현의 실제 동작과 도구 실행은 별도입니다.
