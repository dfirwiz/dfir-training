학습 범위

넷째 날 10강에서는 특정 문자열 하나를 찾는 대신, 메시지의 URL 관측 → 이름 해석 → 외부 연결처럼 시간과 주체가 이어지는 행동 연쇄를 위협 모델로 정리합니다. 독립적인 정상 합성 사례로 관측 지점, 상관 조건, 오탐·누락과 필요한 종단 증거를 구분합니다.

1. 시그니처를 버리는 것이 아니라 행동 문맥을 더합니다

알려진 위험 문자열을 정확히 잡는 시그니처는 여전히 유용합니다. 문제는 발신자·제목·URL 모양이 바뀌면 같은 행위가 다른 바이트로 보일 수 있다는 점입니다. 그래서 “이 문자열이 나왔는가?”에 더해 “어떤 주체가 어떤 순서로 무엇을 했는가?”를 묻습니다.

공항의 수하물 검사를 비유로 들어볼게요. 금지 물품 목록은 시그니처에 가깝고, 수하물이 주인 없이 여러 구역을 비정상적으로 이동하는지는 행동 분석에 가깝습니다. 하지만 네트워크에서는 한 센서가 전체 여정을 보지 못하고, NAT·공유 리졸버·암호화가 주체를 가릴 수 있다는 한계가 있습니다.

접근강점주요 한계검증 질문
시그니처알려진 정확한 패턴을 빠르게 후보화변형·암호화·새 인프라에 약할 수 있음어떤 바이트·필드가 일치했나?

2. 먼저 자산·행위·관측 지점을 모델링합니다

독립적인 합성 사례를 정의해 봅시다. 메일 시스템이 사용자에게 https://notice.example/quarterly 링크가 있는 승인된 모의 교육 메시지를 전달합니다. 단말 192.0.2.24는 내부 리졸버 192.0.2.53을 사용하고, 리졸버는 외부에서 notice.example → 203.0.113.80 응답을 얻습니다. 이후 단말이 그 주소의 443/TCP로 연결합니다.

이 사례는 실제 피싱, 실제 도메인, 실제 패킷이 아닙니다. 목적은 공격을 재현하는 것이 아니라 어떤 로그가 어느 사실을 말할 수 있는지 연습하는 것입니다.

3. 단계별로 관측 사실과 빈칸을 적습니다

공유 리졸버의 외부 질의만 보인다면 DNS의 source는 사용자 단말이 아니라 리졸버입니다. DNS 응답 주소와 이후 외부 연결 주소가 같더라도 CDN·공유 호스팅·캐시·TTL 때문에 우연히 겹칠 수 있습니다. 주소 하나만으로 동일 서비스나 악성 행위를 확정하지 않습니다.

4. 시간 창은 계산하되 인과관계로 오해하지 않습니다

합성 타임라인을 숫자로 풀어 보겠습니다. 메시지 관측은 10:02:00, DNS 질의는 10:14:20, 외부 연결은 10:14:23이라고 합시다.

  • 메시지→DNS: 12분 20초 = 12 × 60 + 20 = 740초
  • DNS→연결: 3초 = 10:14:23 - 10:14:20

3초라는 근접성은 상관 후보를 강하게 만들지만 인과관계를 증명하지 않습니다. 센서 시계가 2초 빠르고 리졸버 로그가 1초 느리면 관측 차이는 최대 3초 달라질 수 있습니다. NTP 상태, 로그 수집 지연, 시간대와 밀리초 정밀도를 보존합니다.

조건을 바꾸면

연결이 40분 뒤라면 캐시·브라우저 사전 조회·사용자 지연을 고려해야 합니다. DNS가 없는데 연결만 보이면 캐시, hosts 파일, 암호화 DNS, 직접 IP 사용, 수집 누락을 가설로 둡니다. “DNS가 없으니 관련 없음”으로 단정하지 않습니다.

5. 상관 규칙은 주체·대상·시간을 함께 요구합니다

안전한 탐지 설계는 세 조건을 따로 적습니다. 첫째, 주체는 같은 단말·사용자·세션인가요? 둘째, 대상은 URL의 이름, DNS 답, 외부 연결 주소가 정책상 연결되나요? 셋째, 시간은 업무 기준선에 맞는 창 안에 있나요?

관측 A: 메시지에서 도메인 D를 추출
관측 B: 내부 주체 H가 D를 조회
관측 C: H가 D의 유효 응답 주소 중 하나로 연결
판단: A·B·C가 시간 창 안에서 이어지면 조사 후보 생성

이것은 실행 코드가 아니라 의사코드입니다. 실제 구현에서는 URL 정규화, DNS TTL, CNAME 연쇄, 다중 A/AAAA, NAT 전후 주소, 프록시, 개인정보 보존 기간을 설계해야 합니다. 일치하지 않은 단계도 버리지 말고 “어느 관측이 없었는지” 기록해야 누락 원인을 찾을 수 있습니다.

6. 방어 심층화는 예방 실패 뒤의 관측까지 준비합니다

방화벽·메일 필터·사용자 교육은 중요하지만 모든 변형을 막는다고 가정할 수는 없습니다. NIST의 제로 트러스트 원칙도 네트워크 위치만으로 암묵적 신뢰를 주지 않고, 자산·통신 상태를 지속적으로 수집해 정책을 개선하도록 요구합니다. 이 강의의 행동 연쇄는 “침해를 전제로 공포를 키우자”가 아니라, 예방 통제가 놓친 상황에서도 빠르게 조사할 증거를 준비하자는 뜻입니다.

MITRE ATT&CK의 현재 데이터 구성요소는 흐름 메타데이터를 주소·포트·프로토콜·시각·용량을 담은 세션 수준 관측으로 설명하고, Passive DNS는 시간에 따른 도메인→주소 관계를 보존하는 자료로 설명합니다. 둘을 메일·종단 기록과 연결하면 단일 센서보다 강한 가설 검증이 가능합니다.

운영 판단

후보가 생성되면 자동 격리부터 하지 않습니다. 먼저 허용 목록, 자산 중요도, 사용자·업무 일정, 동일 도메인의 조직 기준선과 종단 프로세스를 확인합니다. 조치는 증거 수준과 조직 정책에 맞춰 단계적으로 적용합니다.

복습과 해설

1. 행동 탐지는 시그니처를 대체하나요?
아닙니다. 정확한 알려진 패턴과 여러 관측의 시간·주체 상관은 서로 다른 장점이 있어 함께 사용합니다.
2. DNS 응답 뒤 3초 후 같은 주소로 연결되면 사용자가 링크를 클릭한 것이 확정되나요?
아닙니다. 강한 상관 후보일 뿐입니다. 캐시·사전 조회·공유 주소·시계 차이를 고려하고 단말·프록시 기록을 확인합니다.
3. 외부 센서에서 리졸버의 DNS 질의를 보았을 때 원래 단말을 바로 알 수 있나요?
보통 알 수 없습니다. 내부 리졸버 로그나 클라이언트 DNS 기록이 있어야 원래 요청 주체를 연결할 수 있습니다.
4. 연결이 없으면 안전하다고 말할 수 있나요?
아닙니다. 차단·사용자 취소일 수도 있지만, 수집 누락·다른 경로·암호화 DNS·직접 IP 사용일 수도 있습니다.
5. 조사 후보를 침해 확정과 구분하는 가장 중요한 질문은 무엇인가요?
같은 주체가 같은 대상을 시간 창 안에서 실제로 이어 갔는지, 그리고 종단·서버 결과가 무엇인지 묻는 것입니다.

공식 자료와 확인일

2026-11-25에 NIST SP 800-207의 자산·통신 지속 관측과 암묵적 신뢰 배제 원칙, MITRE ATT&CK Network Traffic Flow 데이터 구성요소 2.2, MITRE ATT&CK Passive DNS 데이터 구성요소 2.0를 확인했습니다. 합성 타임라인은 교육용이며 실제 메시지·DNS·캡처·외부 시스템 시험을 사용하지 않았습니다.
