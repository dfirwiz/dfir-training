- 친근한 대화체와 자연스러운 질문·답변을 사용하되 특정 작가의 문장을 재현하지 않습니다.
- 교재·워크북·실습 자료의 역할과 실제 접근·실행 범위를 구분합니다. 자료가 없다고 단정하기 전에 접근 가능한 위치와 기존 기록을 확인합니다.
- 표와 그림은 본문을 대신하지 않습니다. 그림에는 제목·방향·범례 등 필요한 설명을 붙이고 모바일에서 내부 스크롤을 제공합니다.
- 최신 공식 자료의 확인 날짜와 링크, 관측·가설·추가 증거의 구분, 조건 변경과 오해를 다루는 복습 및 즉시 읽는 해설을 유지합니다.
- 게시할 때 승인된 설명 순서·문단·비유·예시·표·복습 해설을 축약하지 않습니다. Mermaid는 같은 노드·분기·되돌아가는 관계의 SVG로 옮기며 본문 출처 링크를 보존합니다.
- 공개 페이지에는 교재 원문·화면·PDF·실습 파일·개인 경로를 게시하지 않습니다. 개정 완료와 원래 진도 완료를 별도 기록하고, 개정을 이유로 자동 연재를 다시 켜지 않습니다.

### 설명의 깊이와 채팅 승인본 유지

사용자는 채팅에서 검토한 상세한 해설을 선호하며, 웹사이트로 옮길 때 설명이 간결해지는 것을 원하지 않습니다. 웹사이트도 같은 깊이의 강의 노트로 작성합니다.

- 채팅에서 승인된 본문이 있으면 설명 순서, 이유와 배경, 비유, 예시, 비교 표, 질문과 해설, 한계와 최신 보충을 빠뜨리지 않고 옮깁니다. 웹 형식으로 옮기는 과정에서 문단을 요약하거나 여러 설명을 한 문장으로 합치지 않습니다.
- 현재의 1강 본문을 설명 깊이와 말투의 기준으로 삼습니다. 처음 읽는 독자가 개념, 왜 중요한지, 구체적인 상황, 어떻게 판단하는지를 따라갈 수 있도록 충분한 연결 문장을 씁니다.
- 표와 다이어그램은 본문의 설명을 돕는 자료입니다. 본문을 표의 짧은 문구로 대체하거나 키워드만 나열하지 않습니다. 복습의 핵심 질문과 해설은 바로 읽을 수 있게 제시합니다.
- 사용자의 추가 질문과 그 답변은 관련 회차 안에 문맥을 유지해 통합합니다. 특히 현대에도 패킷 분석이 중요한 이유와 암호화의 한계를 균형 있게 설명합니다.
- 문서가 길어지면 목차와 소제목으로 읽기 쉽게 구성합니다. 필요한 경우 회차를 나누되 설명을 생략해 길이를 줄이지 않습니다. 글자 수를 채우기 위한 반복도 피합니다.
- 게시 전 승인된 설명과 대조해 주요 문단, 예시, 비교, 질문의 누락을 점검합니다. 사실 오류를 바로잡거나 공개 사이트의 과정 명칭을 조정할 수 있지만, 그 과정에서 교육 내용을 축약하지 않습니다.


개념을 자연스러운 한국어로 쉽게 해설하고 원리, 구체적 사례, 해석의 한계, 복습을 연결합니다. 해당 주제에 유용한 표나 정확한 다이어그램을 포함합니다. 패킷으로 확인 가능한 사실, 단독으로 확정할 수 없는 부분, 함께 볼 로그를 구분합니다.

최신 보충은 공식 문서와 표준 등 1차 출처를 조회해 확인 날짜와 본문의 근거 링크를 붙입니다. 과거의 설명에서 현재에도 유효한 부분과 수정이 필요한 부분을 구분합니다. 도구 사용법, 필터와 옵션을 확인합니다. 재현하지 않은 출력은 가상 예시라고 명시하고 문서용 주소를 사용합니다. 실습 데이터가 없으면 독립적인 복습 문제를 제공하며 실습을 실행했다고 주장하지 않습니다.

원본 PDF, OCR 전문, 교재 화면, 개인 식별 정보, 업로드 식별자, 비공개 메모를 공개 저장소에 넣지 않습니다. 공개 페이지에는 타사 과정 번호를 사용하지 않습니다. 기초 지식을 설명하는 자체 구성과 예제를 작성합니다.

## 게시 절차

1. 최신 main과 진행 정보를 읽고 중복 작업과 동시 변경을 확인합니다.
2. 다음 미완료 학습 범위를 읽고 필요한 그림은 실제 페이지와 대조합니다.
3. 내용을 작성하고 위 기준으로 검토한 뒤 공개 상태와 진행 정보를 함께 갱신합니다.
4. `python3 scripts/build_notes.py`를 실행해 페이지와 목록을 갱신합니다.
5. HTML 구조, 내부 링크와 앵커, 모바일에서 표·그림·코드의 읽기 가능성을 확인합니다.
6. 관련 파일을 하나의 커밋으로 main에 반영합니다. 브랜치가 바뀌면 다시 읽고 통합하며 강제 덮어쓰기를 하지 않습니다.
7. GitHub Pages 배포 결과를 확인합니다. 실패했으면 성공했다고 보고하지 않습니다.

페이지 범위는 순차 작업을 위한 초기 분할이며, 내용의 연결이 끊기면 다음 회차와 경계를 조정하고 진행 정보에 기록합니다. 기초 과정 마지막 회차까지 완료하면 자동 연재를 중지합니다.

본문은 교재의 페이지 번호가 배정되었다는 이유만으로 검토 완료 처리하지 않는다. 원문 학습 항목·작은 예제·실습 요구 조건과 실제 노트 위치를 연결한다. 실습 파일의 레코드 수 검사는 모든 문제의 풀이 완료가 아니다. 미완료 강의에는 축약 초안·상세 개정 대기를 명시한다. 목차는 ul.toc-list와 list-style:none을 유지하여 제목 번호만 한 번 표시한다.


## 2026년 11월 3일 둘째 날 매시간 자동 개정 승인

위 순차 개정 요청 이후 사용자는 한 시간에 한 번씩 다음 강의를 자동 업데이트하도록 명시적으로 승인했다. 이 추가 승인에 따라 automation 자동화가 현재 채팅에서 매시간 한 강의씩 상세 개정·검증·게시를 진행한다. 기존의 시간 간격 미지정 기록은 그 이전 요청 당시의 기록이다. .learning/part-02-progress.json의 editorial_revision을 읽어 다음 미완료 한 강의를 고르고, 이미 개정·배포된 강의를 반복하지 않는다. 이전 배포가 대기 중이면 먼저 확인하고 동일 회차의 중복 실행과 오래된 파일 덮어쓰기를 피한다. 첫째 날 자동화는 변경하지 않는다. 둘째 날 마지막 회차와 전체 교재·워크북 최종 누락 점검이 통과하면 전체 완료를 기록한 뒤 해당 매시간 자동화를 중지한다. 진행이 바뀌지 않았을 때는 조용히 유지하며 강의 게시 완료·실패·사용자 조치 필요·전체 완료만 알린다.

## 2026년 11월 3일 브라우저 검증 재개와 게시 승인

사용자는 브라우저 사용을 허용하고 보류된 4강을 검증·게시하라고 다시 명시했다. 이번 대화에서는 공개 HTTPS 사이트의 열기와 화면 캡처가 정상 동작함을 확인했다. 이전 자동 실행의 브라우저 비활성화 오류가 영구 설정 변경으로 해결됐다고 추정하지 않는다. 로컬 파일 URL은 별도 정책으로 허용되지 않았으며, 이를 다른 주소·프로그램으로 우회하지 않는다.

자동 실행은 먼저 허용된 공개 사이트의 HTTPS 페이지에서 브라우저 접근·캡처 가능 여부를 확인한다. 원고와 저장 바이트·정적 검사를 완료한 뒤 사용자가 게시를 승인한 공개용 독립 본문만 main에 반영하고, 실제 HTTPS 게시 페이지에서 데스크톱·모바일의 표·그림·코드를 검증한다. 브라우저 검증과 배포 확인 전에는 완료 목록을 진행시키지 않고 publication_pending/active_lesson에 기록한다. 화면 문제를 발견하면 해당 회차만 바로 고치고 다시 검증한다. 원본 PDF·실습 파일·개인 자료는 공개하지 않는다.

권한이나 접근이 다시 차단되면 실제 오류의 종류와 확인하지 못한 검증을 기록하고 준비한 원고를 보존한다. 다음 실행은 active_lesson과 보류 원고를 우선 재개하며 같은 강의를 다시 쓰지 않는다. 설정 변경 여부를 확인하지 않고 허용 완료를 주장하거나 모든 사이트의 권한을 확대하지 않는다. 날마다 1강부터의 강의 번호와 절 목차의 중복 번호 방지 규칙을 계속 유지한다.
