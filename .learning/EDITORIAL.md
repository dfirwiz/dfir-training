# 노트 작성과 게시 기준

공개 코스명은 **네트워크 트래픽 분석과 위협 탐지**입니다. 기존의 한국어 중심 디자인과 Pretendard, Inter, JetBrains Mono 폰트를 유지합니다.

## 진행 정보

- `content/course.json`: 회차 순서, 제목, 학습 범위와 공개 상태
- `.learning/progress.json`: 완료 회차와 다음 시작점
- `content/notes/<slug>.html`: 독립적으로 작성한 본문
- `scripts/build_notes.py`: 본문과 목차로 정적 페이지 및 첫 화면 목록 생성
- `notes/<slug>.html`: 실제 배포 페이지

## 한 회차의 내용

개념을 자연스러운 한국어로 쉽게 해설하고 원리, 구체적 사례, 해석의 한계, 복습을 연결합니다. 해당 주제에 유용한 표나 정확한 다이어그램을 포함합니다. 패킷으로 확인 가능한 사실, 단독으로 확정할 수 없는 부분, 함께 볼 로그를 구분합니다.

최신 보충은 공식 문서와 표준 등 1차 출처를 조회해 확인 날짜와 본문의 근거 링크를 붙입니다. 과거의 설명에서 현재에도 유효한 부분과 수정이 필요한 부분을 구분합니다. 도구 사용법, 필터와 옵션을 확인합니다. 재현하지 않은 출력은 가상 예시라고 명시하고 문서용 주소를 사용합니다. 실습 데이터가 없으면 독립적인 복습 문제를 제공하며 실습을 실행했다고 주장하지 않습니다.

원본 PDF, OCR 전문, 교재 화면, 개인 식별 정보, 업로드 식별자, 비공개 메모를 공개 저장소에 넣지 않습니다. 공개 페이지에는 타사 과정 번호를 사용하지 않습니다. 기초 지식을 설명하는 자체 구성과 예제를 작성합니다.

## 게시 절차

1. 최신 main과 진행 정보를 읽고 중복 작업과 동시 변경을 확인합니다.
2. 다음 미완료 학습 범위를 읽고 필요한 그림은 실제 페이지와 대조합니다.
3. 내용을 작성하고 위 기준으로 검토한 뒤 공개 상태와 진행 정보를 함께 갱신합니다.
4. `python3 scripts/build_notes.py`를 실행해 페이지와 목록을 갱신합니다.
5. HTML 구조, 내부 링크와 앵커, 모바일에서 표·그림·코드의 읽기 가능성을 확인합니다.
6. 관련 파일을 하나의 커밋으로 main에 반영합니다. 브랜치가 바뀌면 다시 읽고 통합하며 강제 덮어쓰기를 하지 않습니다.
7. GitHub Pages 배포 결과를 확인합니다. 실패했으면 성공했다고 보고하지 않습니다.

페이지 범위는 순차 작업을 위한 초기 분할이며, 내용의 연결이 끊기면 다음 회차와 경계를 조정하고 진행 정보에 기록합니다. 기초 과정 마지막 회차까지 완료하면 자동 연재를 중지합니다.
