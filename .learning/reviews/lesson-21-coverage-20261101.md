## 현재성·예제 검산

- GNU Grep 공식 문서에서 부정 집합·범위·로캘·앵커·반복을 확인했습니다. GNU grep 3.11, LC_ALL=C에서 자체 입력 15건의 출력과 종료 상태를 비교했습니다. 문서 버전과 설치 버전을 구별합니다.
- 첫 식의 7문자 부분 일치, 둘째 식의 불일치/상태1, 셋째 식의 15문자 전체 일치를 확인했습니다. 한 자리 숫자 입력에서 앞 두 식은 느낌표 전까지 일치합니다. +가 요구하는 한 문자가 공백이어도 됨을 확인했습니다.
- 시작 앵커 제거 뒤 2 flows 일치, 첫 식에 끝 앵커 추가 뒤 실패를 검산했습니다. 입력·앵커·수량 중 한 조건씩 바꿔 원인을 분리했습니다.
- 마지막 식의 앞부분 부재·뒷부분 부재·숫자 두 묶음 실패와 공백 없는 Check42flows·구두점 !42? 성공을 확인했습니다. 시각을 붙인 전체 가상 로그는 실패하고 메시지 부분은 성공함도 구별했습니다.
- PCRE2 공식 알고리즘 문서로 엔진별 일치 선택 차이를 유지했습니다. API 문서의 match_limit·한도 오류 부분을 직접 찾아 읽어 정상 불일치와 자원 한도 실패를 구별했습니다. 성능 시험·한도 오류 재현·운영 설정 변경은 수행하지 않았습니다.
- Suricata 8.0.7 공식 HTTP 문서의 http.uri/http.uri.raw와 정규화 사례를 직접 읽었습니다. 해당 버전 문서의 버퍼 차이를 설명했으며 Suricata·실제 패킷을 실행했다고 하지 않습니다.
- 현재에도 유효한 식의 구조와 보완할 엔진·로캘·버퍼·오류 해석을 구별하고 본문에 날짜·공식 근거 5항을 기록했습니다.
- SVG의 첫 부분 일치 폭 240+40=280, 전체 폭600은 각각 문자6/1/전체15에 40단위를 곱한 값입니다. 마지막 식은 240/80/280의 폭으로 6/2/7문자를 나타냅니다. 길이와 구간·접근성 제목을 검산했습니다.
