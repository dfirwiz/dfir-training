## 현재성 보완

- 단편화의 정상 구조와 보안·운영 위험은 유효합니다. 관측만으로 공격·숙련도·오구성을 확정하지 않았습니다. 역사적 CVE는 현재 자산의 버전·수정·실제 영향 증거와 구분했습니다.
- EDNS는 지원 수신 용량이지 실제 응답 길이가 아닙니다. RFC9715는2025년 Informational 문서임을 명시하고 UDP 단편화 회피·TCP 전환, 기본1400 및 더 작은 값,1232의 계산 배경을 조건부로 설명했습니다. 실제 제품의 현재 설정은 확인한 것으로 꾸미지 않았습니다.
- MTU를 넘는 모든 IPv4가 무조건 조각나는 것은 아닙니다. DF·오류·오프로딩·전송계층 분할을 구분했습니다. 손실 시 IP자체가 자동 재송신하거나 상위 계층이 반드시 같은 IP조각을 만든다고 설명하지 않았습니다.
- IPv6 라우터는 전달 중 단편화하지 않습니다. RFC8201의 PMTUD 구현 요구를 확인해 원문의 무조건 필수 주장을 보완하고,2020년 RFC8899의 DPLPMTUD를2021년 이후에 새로 생긴 것으로 소개하지 않았습니다.
- MF는 데이터 위치 관계이며 도착 순서가 아닙니다. Offset은 위치이지 앞 조각 수가 아니고, 첫/끝 조각 관측과 재조립 완료는 다릅니다.
- 기본 최대 크기로 조각내는 흔한 예제와 RFC791이 허용하는 다른 크기 생성·재단편화 가능성을 구분했습니다. 원래 헤더 사본은 모든 옵션·TTL·체크섬의 완전한 동일 복사를 뜻하지 않습니다.
- 8192가지 값의 최대는8191, 환산 최대65528이며 실제 유효성에는 전체 IP길이·헤더·끝 위치가 함께 필요합니다. 끝이 아닌 IP데이터의8배수 조건을 마지막 데이터나 IP전체 길이에 무조건 적용하지 않았습니다.
- IP재조립·TCP스트림·TLS복호화·응용처리를 단계별로 구분했습니다. 패킷 분석의 가치와 암호화 가시성의 한계를 유지합니다.
- RFC·공식 공급자 보안 권고·Wireshark 자료를2026년11월1일 조회하고17개 근거와 확인일을 본문에 기록했습니다.

## 자체 계산과 구조 검증

모든 가상 통신 주소는 문서용 범위입니다. 원본 PCAP·취약점 실험을 실행한 결과는 없습니다. 세 조각의 데이터 구간·길이만 정한 가상 예시이며 원시 페이로드 출력으로 제시하지 않습니다.

- 마스크R8000/DF4000/MF2000/Offset1fff와2005 AND1fff=5,5×8=40을 검산했습니다.
- A2000:MF1/Offset0/데이터40, B2005:MF1/Offset5/데이터40, C000a:MF0/Offset10/데이터3을 검증했습니다. 데이터 구간[0,40),[40,80),[80,83)은 겹침·누락 없이0~82를 채웁니다.
- 합계40+40+3=83, 원래20+83=103, 조각60+60+23=143, 추가헤더40을 확인했습니다. A와C만 있으면[40,80)의40바이트가 비며, 확보43과 끝83을 구분했습니다.
- 2^13=8192,8191×8=65528,2^16-1=65535,1280-40-8=1232를 검산했습니다. 마지막3바이트는8의 배수가 아니어도 된다는 규칙과 충돌하지 않습니다.
- 홈페이지+노트14개, 로컬 링크·자산784개 및 앵커, 태그 균형·중복ID·h1을 검사했습니다. 새 본문18절·표3개·SVG2개·참고17개·직접 보이는 주요 복습10개와 추가 연습을 확인했습니다. SVG XML·접근성 제목, 표caption/thead/tbody, 기존 가로 스크롤·반응형 스타일을 점검했습니다.
- 기존 폰트·어두운 배경·민트 강조와 생성 스크립트를 유지했습니다. 실제 브라우저 시각 검증은 수행하지 못했으며 구조 검사와 구분합니다.
