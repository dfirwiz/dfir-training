# 4강 원문 대응과 검토 기록

확인일은 2026년 11월 1일입니다. 대상 학습 범위는 인쇄 31~45쪽입니다. 페이지 전체를 OCR로 읽고 모든 페이지의 이미지와 표·그림을 대조했습니다. 원문 전문이나 화면은 저장소에 포함하지 않습니다.

| 학습 범위 | 확인한 개념과 학습 목표 | 노트 대응 절 |
| --- | --- | --- |
| 31 | 단원 안내와 진법 학습으로의 전환 | purpose |
| 32 | bit, nibble, byte, word 계열과 문맥별 크기 | units |
| 33 | 십진수의 자리값과 0번째 자리, 자리올림 | place-value |
| 34 | 이진수의 숫자 종류와 최댓자리, 십진수 변환 | binary |
| 35 | 16진수 A~F, 접두어와 8진수 관습 | hex, modern |
| 36 | 0~F와 네 비트의 전체 대응표, 10과 0x10의 구별 | hex |
| 37 | 진법 간 같은 값의 표현, 비트 설정과 플래그 | binary, conversion |
| 38 | 이진수 네 자리와 16진수 한 자리, 상·하위 니블과 바이트 | nibbles, conversion |
| 39 | 각 니블의 값과 전체 바이트에서의 가중치 차이 | nibbles |
| 40 | 16비트 필드의 16진수 네 자리와 십진수 변환 | conversion, offset |
| 41 | IPv4 첫 네 바이트에서 Total Length 찾는 연습 목표 | offset, review |
| 42 | 0부터 세는 오프셋, 필드 두 바이트와 길이 해석 | offset, review |
| 43 | tcpdump 옵션, 요약 줄, 16바이트 덤프 줄, 계층 경계 | dump |
| 44 | IPv4 Identification 위치와 폭을 먼저 찾는 방법 | id |
| 45 | Identification 값의 변환, 도구 결과와의 교차 검증 | id, modern, review |

## 예시와 근거

원본 실습 PCAP은 제공되지 않았습니다. 예제 필드 값과 IPv4/UDP/DNS 바이트는 별도로 구성했고, 본문에 학습용 예시라고 명시했습니다. 덤프는 원본 파일을 실행한 출력이 아닙니다. Python의 산술·바이트 변환 예제는 직접 실행했습니다.

IPv4 헤더·전송 순서는 RFC 791, TCP Data Offset은 RFC 9293, IPv4 ID의 의미는 RFC 6864와 대조했습니다. word는 일률적인 크기로 일반화하지 않고 Microsoft의 타입 정의와 프로토콜의 32비트 단위를 구분했습니다. 현재의 Wireshark 숫자 표기와 바이트 표시, Python 변환 함수, tcpdump 출력 옵션을 공식 문서에서 확인했습니다. 근거 링크는 본문에 제공합니다.

## 계산과 구조 점검

- 0xA6 = 166 = 10100110 이진수
- 0xB3 = 179 = 10110011 이진수
- 0x0068 = 104, IHL 6 × 4 = 24, IP 데이터 104 - 24 = 80
- 0x023B = 571, 반대 바이트 순서는 0x3B02 = 15106
- 독립 구성 패킷: IP 20 + UDP 8 + DNS 29 = 57바이트
- IP Total Length 57, Identification 571, IP Protocol 17, UDP 포트 53000→53, UDP Length 37과 실제 바이트의 일치 확인
- IPv4 헤더 체크섬의 산술 일치 확인. 이 검증을 실제 네트워크 통신이나 공격 분석 결과로 해석하지 않음
- 목차, 참고문헌, 내부 링크, 중복 ID, 이전·다음 노트 및 진행 상태 점검
- 이전 상세 해설의 수준을 기준으로 정의·이유·절차·예제·전제·한계와 복습 해설을 본문에 포함

별도 실습 파일과 포켓 레퍼런스 없이도 연습 목표를 따라갈 수 있도록 위치와 바이트를 본문에 제시했습니다. 브라우저 및 미리보기 인프라의 기존 제한으로 실제 화면의 시각 검증은 수행하지 못했습니다. 기존 반응형 스타일을 유지하고 표와 SVG의 구조를 확인했습니다.
