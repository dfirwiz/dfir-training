# 셋째 날 1강 교재 대조와 검산 · 2026-11-19

셋째 날 교재에서 인쇄 4~13쪽에 해당하는 PDF 6~15쪽의 내장 텍스트와 각 페이지의 그림·표·화면을 직접 확인했다. 목차로 뒤의 주제 범위를 확인했다. 셋째 날 워크북과 원본 캡처는 이번에 접근하지 못했다. 첫 강의의 표본과 규칙은 독립적인 정상 UDP 예제로 설계했다.

| 교재 범위 | 학습 목표 | 공개 본문과 확인 |
| --- | --- | --- |
| 4~5쪽 | 프로토콜 분석에서 시그니처 기반 탐지로, Scapy 도구와 Python 활용 | `goal`, `fields`, `build`. 대화형 탐색과 재현 가능한 파일 시험을 구분 |
| 6~7쪽 | 특징을 문장과 규칙으로 정리, 검증 입력의 이유와 독립 검토 | `cases`, `rule`. 교재의 행위·규칙·수치를 복제하지 않고 주소·방향·포트·데이터 위치를 비교하는 가상 UDP 다섯 표본으로 학습 |
| 8~10쪽 | 계층과 필드 발견, 클래스와 인스턴스, 기본값·명시 입력·타입·오류 시점 | `fields`, `values`, `verify`. `ls`/`lsc`, 점 표기, 바이트 문자열, 조립 전후 확인 |
| 11쪽 | Ethernet부터 데이터까지 계층을 쌓고 상위 프로토콜을 확인 | `stack`, `verify`. 표본의 14/20/8/6바이트 지도, EtherType·Protocol·길이와 체크섬 검산 |
| 12쪽 | PCAP 저장, 재열기·시각 확인 | `build`, `verify`. 5개의 합성 프레임을 쓰고 다시 읽음. 운영망에 송신하지 않음 |
| 13쪽 | 오프라인 규칙 실행의 기대 결과, 경보의 한계와 자체 규칙 | `rule`, `triage`, `review`. 제작사 Snort 3 문법으로 격리된 파일의 명령을 안내하고 경보 엔진 결과를 주장하지 않음 |

Scapy 2.5.0에서 본문의 Python 코드를 두 번 실행했다. 캡처가 바이트 단위로 같았고, 파일의 링크 유형·레코드 경계·시각·헤더 종류·주소·UDP 포트와 길이·IPv4/UDP 체크섬을 별도 파서와 계산으로 확인했다. 가상 표본 1·5만 규칙의 기대 조건에 맞았다. IPv4 옵션 4바이트를 넣었을 때 데이터 시작이 42에서 46으로 이동한 것도 확인했다. Scapy 2.7.0은 실행 환경의 인터페이스 열거가 제한되어 초기화하지 못했다. Snort·Suricata와 현장 센서·IPS는 실행하지 않았다.

Scapy·Snort 3 제작사 문서와 IPv4·UDP·문서용 주소 RFC를 2026-11-19에 직접 조회했다. 다음은 인쇄 14쪽부터 저장 캡처를 읽고 변경 전후 필드를 점검하는 범위를 검토한다.
