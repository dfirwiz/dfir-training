# 넷째 날 2강 검토 · 2026-11-25

인쇄 10–20쪽과 해당 PDF 12–22쪽의 텍스트 및 렌더링을 직접 대조했다. 자료의 배치 목적과 방향을 검토하고, 그림과 예제는 별도로 구성했다.

| 인쇄쪽과 학습 목표 | 공개 본문 | 예제·검증 | 잔여 |
|---|---|---|---|
| 10–12 · 보호 대상, 수집 우선순위, 경계 전후와 중요 내부 링크 선정 | `#point`, `#evidence` | 같은 스위치에 있는 두 서버와 경계 수집의 반례 | 운영망·규정별 배치 검증 미실행 |
| 13–14 · 방향별 복사와 전원·매체·장애 동작 | `#tap` | 독립 SVG로 업무 전이중과 모니터 출력 두 방향 구분. 광 파워 예산은 제작사 자료 확인 | 실제 부품·장애 시험 미실행 |
| 15 · 센서 입력 결합과 부담 | `#balance` | 커널 문서에서 기존 본딩 도구와 현재 관리 경로 확인. 논리 묶음과 엔진의 공통 흐름 처리를 구별 | 본딩·센서 설정은 적용하지 않음 |
| 16 · 미러 포트의 방향, 누락, 용량 | `#mirror`, `#capacity` | 복사본 전송의 상한 20Gb/s, 0.2초의 처리량 차이 75MB 검산. 포트의 TX·RX 기준 확인 | 실제 장비 큐·누락 측정 미실행 |
| 17–19 · 단일·다중 입력, 집선·출력 선택, 선별 | `#mirror`, `#capacity`, `#balance` | 출력 포화 시 손실 가능성, 기록용 출력과 탐지용 출력의 범위 비교 | 제품별 특성·바이트 통계 미실행 |
| 20 · 흐름 단위 분배, 센서 처리량, 서비스별 분배 | `#balance`, `#evidence`, `#review` | 문서용 주소의 정상 TCP 양방향을 한 워커에 보내는 조건과 패킷별 분배의 반례 | 실제 Zeek·패킷 브로커 실행 미수행 |

Cisco의 SPAN, Gigamon의 광 파워 예산, Linux 커널의 본딩, Zeek의 흐름 분배를 각 공식 문서에서 확인했다. 별도 워크북과 캡처는 이 강의에서 직접 대조·실행하지 않았다.
