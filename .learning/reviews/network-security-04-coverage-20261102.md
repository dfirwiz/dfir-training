## 바로잡은 주요 설명

긴/무작위 이름·희귀 TLD·평판·ASN·국가·NULL/TXT 하나로 감염을 확정하지 않습니다. 공유 주소에는 중요한 정상 서비스가 있을 수 있습니다. 전달 리졸버 기록에서 최초 단말을 바로 특정하지 않습니다. passive 검색도 검색 서비스에 관심 지표를 노출할 수 있습니다. Whois 문자열 파싱을 보편적인 현행 방식으로 사용하지 않습니다.

터널은 항상 성공하거나 반드시 대량인 것이 아닙니다. 승인 리졸버 경유도 가능합니다. 정상 보안 제품의 DNS 데이터 교환도 구분합니다. 이름 255글자와 DNS 전송 형식 255옥텟을 혼동하지 않습니다. IDN 탐지는 각 레이블에서 수행하며 xn-- 자체가 악성/유효성 증거는 아닙니다. 문자 변환은 IDNA 전체 검증과 구별합니다.

DoH는 JSON 필수/HTTP2 POST 고정이 아닙니다. HTTP3·DoQ를 구분합니다. DNSSEC는 개인키로 RRset 서명·공개키 검증이며 기밀성/콘텐츠 안전성/관리 계정 보호를 대신하지 않습니다. 카나리아 신호는 범용 강제가 아닙니다. TLS 검사만을 유일한 답으로 제시하지 않습니다. DoH가 정확히 3개 패킷이라는 가정을 제거했습니다.

## 수행한 검증

본문 27절, 문단 155개, 표 4개, 코드/계산/가상 출력 13개, SVG 5개, 복습 18문항과 해설의 렌더링을 확인했습니다. 코드 블록 보존, XML 구조, 문서 내부/상대 링크·앵커, 중복 ID와 공개 본문의 타사 강의 식별자 노출 여부를 검사했습니다. 1~3강 교육 본문은 이전 게시본과 동일합니다. 다른 과정의 최근 갱신도 먼저 반영한 후 홈페이지의 이 과정 카드만 수정했습니다.

로컬 데스크톱과 390px 모바일에서 제목·목차·이전 강의 연결·그림 5개·표/코드 내부 스크롤을 확인했습니다. 그림의 선과 설명이 겹친 부분을 수정해 재검사했습니다. 문서 전체의 가로 넘침은 없었습니다. 배포 완료는 게시 작업의 상태와 공개 페이지에서 별도로 확인합니다.

## 실행하지 않은 것

실제 DNS 질의·등록정보/평판 서비스에 지표 제출·DNS 설정 변경·PCAP 분석·터널 도구 실행·TLS 복호화·차단 정책 적용은 하지 않았습니다. 코드 포인트와 Punycode 자체 예제만 네트워크 없이 실행해 xn--exmple-4nf와 U+0430을 확인했습니다. 나머지 로그·패킷·수치는 자체 가상 예제입니다.
