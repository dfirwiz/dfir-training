# 둘째 날 2강 상세 개정

확인일: 2026-11-03. 이번 실행의 본문 개정 대상은 노트 24 한 강의다. 기존 둘째 날 1강은 유지하고 노트 25~39는 상세 개정 대기로 구별한다. 이전 전체 완료 판단은 철회했다. 페이지 범위의 배정, 레코드 총수, HTML 검사만으로 교육 내용의 완전성을 주장하지 않는다.

## 워크북 실습 요구 조건과 검산

대상: 전자 워크북 표시 필터 실습(2.1)의 준비, 네 문제, 추가 문제와 힌트·해설. 원본 파일의 SHA-256은 7d010c4b73a430fae6a843e807f0a31751f24583a08a0693ec813e4de8fad9d7이다. 원본 108개 레코드에서 관련 필드를 다시 읽었다.

|항목|요구 조건과 풀이|바이트 대조|
|---|---|---|
|준비|원본 보존·버전 기록·필드/단위 선택·각 문제 후 필터 초기화|lab-start|
|문제 1|DNS 질문 이름의 문자열 포함·요청과 응답에도 질문이 존재함|101·102번, lab-dns|
|문제 2|ARP 요청의 Opcode, 개수, 요청 중 자발적 ARP 추가 제한|요청 16개, 송신/대상 프로토콜 주소가 같은 14번, lab-arp|
|문제 3|Echo Reply·IP Total Length<46·Ethernet 최소 길이의 단위|87·89·91번의 IP 길이 29, lab-padding|

|추가|첫 IP 옵션의 오프셋, 옵션 존재 선행조건, UDP 포트의 같은 값에 의한 거짓 양성|26·27·28·92·93번, 조건 생략 시 96번 추가, lab-options|

패딩은 최소 계산과 캡처 실측을 구별했다. 태그 없는 기본 Ethernet 가정에서 최소 데이터 영역은 46바이트이고 IP 길이 29이면 필요한 최소 채움은 17바이트다. 실제 세 레코드는 저장 길이 77바이트, IP 끝 뒤에 0값 34바이트가 있었다. 따라서 실제 바이트 개수가 최소 계산과 동일하다고 주장하지 않는다. 짧은 IP 전체 길이를 IP 헤더 길이나 손상된 runt 프레임으로 오해하는 교재 해설 표현도 바로잡았다.

## 공식 근거 확인

Wireshark 공식 안내서의 저장 필터·표현식·표시 필터 문법·도구 모음·설정 파일·Mark·내보내기·Packet Range, TCP/ARP/DNS 필드 참조를 확인했다. 본문에 해당 위치와 링크를 연결했다. `ip[20:1] == 83`의 단일 바이트 slice 표기는 공식 안내서의 `eth.src[2] == 83` 및 n:1 동등 설명과 대조했다. 숫자 필드와 바이트열 표기를 구별했다. 교재의 특정 메뉴 동작과 자동 완성 접두어는 영구적인 현재 동작으로 가정하지 않았다.

## 검증과 실제 실행 범위

HTML 태그 균형, ID 중복, 목차·내부 링크, 기존 앵커의 유지 여부를 확인했다. 첫째 날과 나머지 둘째 날 본문은 현재 main의 내용 해시와 대조했다. 나머지 15강의 생성 페이지에는 상세 개정 대기 안내만 추가하며 본문을 개정 완료로 기록하지 않는다. 데스크톱과 모바일에서 본문·표·그림·목차를 시각 확인했다. 게시 뒤 배포와 실제 페이지를 확인하고 성공한 범위만 보고한다.

원본 바이트 검산과 공식 문서 대조를 수행했다. Wireshark GUI, TShark 필터 엔진, GUI 내보내기, 당시 VM의 수신 동작은 실행하지 않았다. 필터 엔진 실행을 하지 않았다는 사실을 본문에서 명시한다. 원본 파일·교재 PDF·텍스트 추출물·교재 화면은 공개 변경에 포함하지 않는다.

다음 개정 대상은 노트 25, 둘째 날 3강(BPF 기준점·읽기 길이·마스크)이다. 한 번에 다음 한 강의를 진행하며, 시간 간격이나 자동화 실행은 새로 설정하지 않았다.
