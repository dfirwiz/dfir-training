# 네트워크 보안 분석 3강 범위·검증 기록

## 원문 범위 대응

진행 범위: 2권 인쇄 31~50쪽. 31쪽은 과정 안내이며 본문 32~50쪽 전체를 독립적인 사례와 설명으로 연결했습니다.

- 32: 이름 조회의 필요성과 실제 접속의 구분 → 1절
- 33~34: 스텁·전달·캐싱/재귀·권한 역할 → 2~3절, 16절의 운영체제·Pi-hole 보충
- 35: 루트·TLD·권한 조회와 캐시 → 4~5절, 그림 1~2
- 36: A·AAAA·NS·CNAME·SOA·NULL·PTR·MX·TXT·SRV 종류 코드 → 15절
- 37~38: A/AAAA, 질문·응답·ID·TTL·외부 주소와 관측 위치 → 6~7절
- 39: PTR 역순과 역방향 존, 위임 → 9절
- 40~42: 다대다·시간 변화·공유 주소 차단 위험·역방향 확인의 한계 → 8~9절, 그림 3
- 43: TXT·SPF·DKIM·제어 확인 → 10절
- 44: CNAME과 순환 → 11절, 그림 4
- 45: MX와 선호도 → 12절
- 46: SRV 형식과 필드 → 13절
- 47: 부모·자식 NS와 위임 → 14절
- 48~49: 질문 이름·복수 A·CNAME 대상·PTR 원래 IP·사용한 리졸버를 읽는 자체 6행 패킷 연습 → 18절
- 50: 원리 종합과 다음 분석 범위 연결 → 19~20절

## 현재 기준 보충

TXT는 개별 character-string의 255옥텟 제한이며, 전체 레코드의 255글자 제한이 아닙니다. SPF 버전은 v=spf1입니다. DKIM은 개인키 서명·공개키 검증입니다. MX의 A/AAAA와 Null MX, SRV 우선순위/가중치와 공개 사용 가능성, CNAME과 HTTP 이동의 차이, 권한 존의 위임 경계, 캐시·부정 캐시·serve-stale, QNAME 최소화, DNSSEC과 암호화의 차이를 필요한 범위에서 보충했습니다.

RFC 1034·1035·1912·2308·2317·2782·3596·4033·5321·6376·7208·7505·7766·8767·9156·9499, Microsoft nslookup/ipconfig, BIND dig, Wireshark DNS 필드, systemd-resolved, Pi-hole 문서를 2026년 11월 2일 조회했습니다.

## 수행한 검증과 한계

20개 절, 본문 125개 문단의 렌더링, 표 4개, 코드·레코드·필터 예시 19개, SVG 4개, 복습 14문항과 즉시 읽는 해설을 확인했습니다. XML 구조와 내부 링크·앵커를 검사했습니다. 1~2강의 교육 본문은 이전 게시본과 동일합니다.

실제 DNS 질의·단말 캐시 수집·원본 PCAP 분석을 실행하지 않았습니다. 명령·주소·레코드·6패킷 연습은 자체 가상 예제임을 본문에서 명시했습니다. 화면 검증과 배포 상태는 게시 절차에서 별도로 확인합니다.

로컬 화면에서 데스크톱과 390px 모바일 레이아웃을 확인했습니다. 그림 네 개의 글자·방향 표시, 문서 전체 가로 넘침 없음, 넓은 표·코드 내부 스크롤을 확인했습니다. 배포 완료 여부는 배포 작업의 결과와 공개 페이지로 별도 확인합니다.
