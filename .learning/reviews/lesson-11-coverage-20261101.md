## 현재성 보완과 학습 깊이

- 기본 ARP의 인증 한계, 동일 링크의 주소 해석, 잘못된 대응 사용으로 경로가 달라질 수 있다는 원리는 유효합니다.
- RFC 826의 기존 항목 갱신/대상인 경우 새 학습과 Linux arp_accept의 gratuitous ARP 조건을 구별했습니다. 모든 수신자가 모든 대응을 새로 학습하거나 어떤 순서의 응답이 반드시 채택된다고 쓰지 않습니다.
- 송신 전달과 회신 전달, 관측/캐시 반영/자산 소유권/응용 결과를 분리했습니다. 일반 IP 프레임 수신과 ARP·MAC 표 학습을 혼동하지 않습니다.
- CAM 포화가 모든 프레임을 모든 VLAN/포트로 퍼뜨리는 보편 동작이라는 설명을 보완했습니다. 정상 unknown unicast와 공격의 구분, 관측 가능성과 변조·경로 장악의 차이를 설명했습니다.
- BPDU Guard, 포트 보안, DHCP snooping, DAI, unknown unicast 억제의 검사 대상을 구분했습니다. 장비 지원과 활성화를 동일시하지 않았습니다.
- DAI의 정적 IP 기준 부재·trusted 우회·바인딩 신뢰·위반 통계의 시간 대응·다른 경로 한계를 설명했습니다. 읽기 전용 조회 명령 4개를 공식 자료로 대조했습니다. 실제 장비 실행 결과는 없습니다.
- TLS 1.3의 보호 전제를 연결해 ARP 경로 변경만으로 암호화 본문 열람·변조를 단정하지 않았습니다. IPv6는 별도 이웃 발견·보호 범위를 확인하도록 연결했습니다.
- 최신 보충은 2026년 11월 1일에 RFC·Linux·Wireshark·Cisco 공식 문서를 조회하고 본문에 12개 근거 링크와 날짜를 기록했습니다.

## 예제·구조 검증

문서용 IPv4/MAC만 사용한 독립 가상 구성입니다. 모든 예제·도식·연표에 실제 결과가 아님을 명시했습니다. 원본의 사설 IP·눈에 띄는 MAC을 복제하지 않았으며, 특정 패킷 순서·OUI로 진위를 판단하지 않습니다.

- 0.025000 - 0.000400 = 0.024600초, ×1000 = 24.6밀리초를 Decimal로 검증했습니다.
- 1500+14+4=1518, 46-28=18, 14+28+18+4=64. 앞 42바이트의 캡처와 회선 최소 프레임을 구분했습니다.
- 홈페이지와 11개 노트의 HTML 태그 균형·중복 ID·h1·로컬 링크/자산 559개·대상 앵커를 확인했습니다. 새 본문 15절, 9개 주요 질문/해설과 추가 연습, 표 4개, SVG XML·접근성 제목을 점검했습니다.
- 표는 가로 스크롤 래퍼, 코드는 기존 pre 스크롤, SVG는 기존 반응형·최소 폭을 사용합니다. 폰트·어두운 배경·민트 강조 디자인을 유지합니다. 실제 브라우저 미리보기 인프라가 없어 시각 검증은 수행하지 못했습니다. 구조 검사를 화면 검증 완료로 보고하지 않습니다.
- 생성 스크립트와 기존 본문은 수정하지 않았습니다. 생성된 탐색·목차·이전/다음 연결만 갱신합니다.

## 진행 상태
