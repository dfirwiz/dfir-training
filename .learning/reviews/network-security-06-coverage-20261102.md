# 네트워크 보안 분석 6강: HTTP 원리 범위·정확성 검토

## 원문과 자료 접근

본 교재 2권 인쇄 89~106쪽(PDF 91~108쪽)을 텍스트로 확인했습니다. URL, POST, 요청·중첩 Referer, 요청/응답 퀴즈, HTTP2 분석 화면을 렌더링해 확인했습니다. 교재 폴더의 별도 워크북·실습 원본은 앞선 검색에서 찾지 못했으며 이번 강의는 해당 실습 실행 결과가 아닙니다. 기존 5강의 합성 PCAP·ZIP도 변경하지 않았습니다. 원본 교재 화면과 악성 사이트 주소는 공개 콘텐츠에 옮기지 않았습니다.

## 주요 정확성 보충

경로가 반드시 디스크 폴더/파일이라는 비유의 한계를 설명했습니다. 질의는 GET 전용이 아니며 POST는 비밀/무기록/무제한을 보증하지 않습니다. 안전·멱등성은 의도한 동작 분류이고 GET도 실제 안전성 보증은 아닙니다. HEAD의 일부 동적 헤더 예외, CONNECT와 암호화의 구분, HTTP 버전 사이 공통 메서드 의미를 설명했습니다.

Accept 가중치·구체성을 고려하고 User-Agent/언어/Referer/Server/Date는 신고·정책·시계 한계를 명시했습니다. XFF는 신뢰 프록시 정책과 우회 경로를 확인합니다. 헤더 순서에는 반복 필드와 의사 헤더의 예외가 있습니다. 쿠키는 모든 후속 요청에 무조건 전송되지 않습니다.

403은 인증 완료의 증거가 아니고, 200은 로그인/실행/침해 성공이 아닙니다. 이동 응답과 후속 접속을 구분하고 304와 HEAD의 본문 부재를 설명했습니다. Content-Length는 문자/패킷 총길이/해제 후 파일 길이와 다를 수 있습니다. gzip과 HTTP1.1 청크 프레이밍을 구분했습니다.

SPDY를 HTTP2의 동의어로 쓰지 않습니다. HPACK과 TLS를 구분하고 Chrome 106의 서버 푸시 기본 비활성화 조건을 보충했습니다. HTTP3는 IETF QUIC 위의 HTTP이며 UDP를 없애거나 단순히 HTTP2를 그대로 UDP에 얹는 것으로 설명하지 않았습니다. HTTP3/QPACK·QUIC 연결/스트림, Wireshark http3.headers.method의 4.2.0 이후 지원을 확인했습니다. 구버전 3.6 화면의 한계를 현행 전체 한계로 일반화하지 않았습니다.

## 공식 근거

2026-11-02 확인: RFC 3986·6455·7541·8441·9000·9110·9112·9113·9114·9204, Mozilla MDN의 메서드/GET/POST/HEAD/CONNECT/헤더/상태/조건부 요청, Chrome 서버 푸시 변경, Wireshark HTTP/HTTP2/HTTP3 필드와 TLS 문서, Python gzip 문서. 근거는 본문 해당 설명 옆에 링크했습니다.

## 직접 수행한 계산

Python 3.12.14에서 문서용 URL을 분해하고 Referer 매개변수를 복원했습니다. POST 폼 본문 17바이트, 단순 HTML 응답 23바이트를 확인했습니다. 한글 HTML은 문자 13개·UTF8 23바이트이고 gzip.compress(compresslevel=9,mtime=0)는 44바이트였으며 해제 뒤 원본 바이트와 일치했습니다. 이는 로컬 자체 예제 계산이며 실사건 패킷 분석 결과가 아닙니다.

## 사이트 검증과 한계

27절·138문단, 표 4개, 코드/메시지/계산 블록 16개, SVG 5개, 복습·해설 20개를 렌더링했습니다. 본문 전체·코드 보존, XML, 내부 링크·앵커, 중복 ID, 공개 강의 식별자 노출을 검사했습니다. 1~5강 본문과 홈페이지 다른 과정은 이전 게시본과 동일합니다.

이번에는 Work 설정에서 로컬 브라우저 사용이 비활성화돼 실제 브라우저·모바일 화면 QA를 수행하지 못했습니다. 이를 우회하지 않고 기존 반응형 CSS/가로 스크롤 구조를 검사했으며, SVG 5개는 별도 정적 렌더링과 한국어 폰트 폭 측정으로 글자·방향·경계를 확인했습니다. 요청/응답 그림에서 선과 범례가 겹친 부분을 수정했습니다. 정적 렌더링은 브라우저 화면 검증을 대신했다는 의미가 아닙니다. 배포와 공개 자원의 바이트 일치는 게시 후 별도 확인합니다.

## 수행하지 않은 분석

실제 외부 HTTP 요청의 조사·라이브 캡처·원본 PCAP 분석·Wireshark 표시 필터 실행·TLS 복호화·실제 공격/파일 실행은 수행하지 않았습니다. 자체 메시지·도메인·제품 이름·시나리오에 기반한 설명입니다. 사이트 검증을 위한 HTTP 요청은 이 교육용 통신 분석과 구분합니다.
