# 2강과 3강 상세 점검 및 보강 기록

점검일은 2026년 11월 1일입니다. 수정된 1강의 설명 깊이, 교재의 해당 학습 범위, 공식 프로토콜 문서와 도구 문서를 기준으로 기존 2강과 3강을 대조했습니다. 핵심 개념이 등장하는지만 확인하지 않고, 초심자가 관찰에서 판단까지 따라갈 수 있는지와 계산의 전제·한계가 설명되어 있는지를 검토했습니다.

## 2강 경고 이름보다 중요한 패킷의 맥락

| 점검 항목 | 확인한 부족한 점 | 반영한 수정 |
| --- | --- | --- |
| 조사 사고 과정 | 가설을 검증한다는 설명은 있었지만 네 단계를 실제 사례에 적용하는 과정이 짧았음 | 관찰과 분석, 가설, 검증과 종합, 보고를 구분하고 Ping Sweep 사례를 각 단계에 대응시킨 표와 연결 설명 추가 |
| ICMP 기초 | ID와 sequence가 반복된다는 관찰에 비해 각 필드의 의미와 요청·응답 대응 설명이 부족했음 | Echo Request·Reply, Identifier, Sequence Number, 반환 데이터의 의미와 한계 설명 추가 |
| 시각 해석 | 간격이 짧다는 설명만 있고 숫자를 읽는 과정이 생략되어 있었음 | 두 시각의 차이 0.000500초를 0.5밀리초로 환산하는 과정 추가 |
| 출력과 필터 | 옵션 표는 있었지만 명령 두 개의 사용 순서와 표본 세 개의 한계 설명이 짧았음 | 요약에서 상세로 들어가는 순서, 양방향 host 조건, 표본의 한계와 ASCII 점의 의미 설명 추가 |
| 도구 식별 | 조건을 맞춰 재현해야 한다는 설명의 배경이 부족했음 | 기본 도구와 출력 지문의 관계, 옵션·버전·권한·환경 차이, 조건부 보고 예시 보강 |
| SYN 스캔 | 응답 표에 필요한 SYN·SYN-ACK·ACK와 서비스 접속의 관계 설명이 짧았음 | 기본 연결 설정 흐름과 탐색의 차이, 호스트 탐색과 포트 탐색의 구별 설명 추가 |
| ICMP 터널 | 터널의 뜻과 정상 Echo의 대응 관계가 충분히 설명되지 않았음 | 터널의 정의, 정상 대응과 의심 정황, 중복·수집 누락 등 다른 원인, SSH 식별 문자열의 해석 한계 추가 |
| 사건 연표와 우선순위 | 전후 로그를 본다는 지침만으로는 실제 기록 방법을 따라가기 어려웠음 | 관측·미확인 구분 연표, 자산·승인·진행 정도·관측 범위를 반영하는 우선순위 질문 추가 |
| 복습 | 주요 질문의 해설이 접힌 UI 안에만 있었음 | 질문과 상세 해설을 본문에 직접 표시 |

확인한 기술적 해석은 다음과 같습니다. ICMP 순번 증가는 항상 강제되는 조건이 아니며, 특정 도구나 공격자 수준을 단일 필드로 확정하지 않습니다. 캡처에서 응답이 없다는 것만으로 무해함이나 차단 성공을 단정하지 않습니다. 공격이 실패했다고 해서 탐지가 오탐이 되는 것도 아닙니다. 이 구분은 유지하고 설명을 보강했습니다.

## 3강 TCP/IP 계층과 캡슐화

| 점검 항목 | 확인한 부족한 점 | 반영한 수정 |
| --- | --- | --- |
| 계층과 주소 | 계층 표는 있었지만 실제 브라우저 요청 및 주소의 역할을 연결하는 설명이 짧았음 | 브라우저 요청 상황, L2·L3·L4 관점, MAC과 IP 및 프로그램 식별의 차이 설명 추가 |
| 송신과 수신 | 캡슐화 정의와 그림에 비해 단계별 해설이 짧았음 | 송신 네 단계와 수신 시 종류·길이·소켓을 따라가는 설명 추가 |
| 길이의 종류 | 값과 공식이 중심이어서 고정·가변·계산 길이의 차이가 충분히 드러나지 않았음 | 세 길이 유형과 32비트 단위 환산, 일반적인 헤더 길이 범위 설명 추가 |
| 옵션 경계 | 옵션·패딩이 있다는 설명만 있고 내부 구조를 읽는 방법이 생략되어 있었음 | 종류·길이·값 구조 및 한 바이트 TCP 옵션의 예외, 패딩 설명 추가 |
| 계산 예제 | 정답과 식은 맞지만 뺄셈과 덧셈의 기준을 따라가는 설명이 짧았음 | IP Total Length에서 Ethernet 헤더를 다시 빼지 않는 이유, 기준 오프셋과 각 단계 계산 설명 추가 |
| 캡처의 완전성 | 잘린 캡처라는 한계만 있고 수치 예시가 없었음 | 1,014바이트 프레임에서 앞의 128바이트만 확보한 경우 실제 TCP 데이터가 58바이트인 예제 추가 |
| 스트림 재조립 | 세그먼트와 메시지 경계의 차이는 있었으나 도구 사용과 한계 연결이 짧았음 | Follow TCP Stream의 역할과 누락 바이트·암호화 처리의 한계 설명 추가 |
| 클라우드 캡슐화 | 미러링 제한은 있었으나 바깥·안쪽 헤더를 실제 조사와 연결하는 설명이 부족했음 | VXLAN 수집 전달의 외부 주소와 원래 통신을 구분하는 설명 추가 |
| 복습 | 핵심 해설이 접힌 UI 안에만 있었음 | 주요 질문과 단계별 해설을 본문에 직접 표시 |

기존의 핵심 길이 계산은 올바른 값을 유지했습니다. 다만 단편화되지 않은 IPv4/TCP, 태그 없는 Ethernet II, FCS를 제외한 프레임이라는 전제를 명확히 하고, 실제 캡처 길이와 논리적 길이를 구별하는 설명을 보강했습니다. IPv6와 QUIC에는 IPv4/TCP 공식을 그대로 적용하지 않는다는 주의도 유지했습니다.

## 검증과 범위

- 교재의 해당 학습 범위에 나오는 주요 개념과 사례를 기존·수정 본문에 대조했습니다.
- ICMP Echo는 RFC 792, TCP는 RFC 9293, 도구 옵션과 캡처 조건은 공식 tcpdump·Nmap·Wireshark 문서, 클라우드 전달은 AWS 문서를 확인했습니다. 근거 링크는 각 노트에 붙였습니다.
- 계산은 0.000500초 = 0.5밀리초, 1000 - 24 - 32 = 944, 14 + 24 + 32 = 70, 128 - 70 = 58, 900 - 20 - 32 = 848을 재확인했습니다.
- HTML 구조, 중복 ID, 본문·목차·참고문헌·이전/다음 노트의 내부 링크와 앵커를 검사했습니다.
- 상세 해설을 표의 짧은 문구로 대체하지 않았고, 가상 사례와 실제 실행 결과를 구분했습니다. 별도의 실습 PCAP을 실행했다고 주장하지 않습니다.
- 1강 본문과 순차 학습 진행점은 유지했습니다. 다음 미완료 회차는 4강입니다.
- 브라우저 및 미리보기 실행 환경의 제한으로 화면의 시각 검증은 수행하지 못했습니다. 기존 반응형 스타일과 다이어그램은 유지했습니다.
