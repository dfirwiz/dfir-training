## 원리·예제·한계

목적지 MAC과 최종 IP 목적지, 링크 브로드캐스트와 IP 주소를 구분했습니다. MAC은 인증된 사용자 신원이 아니며 캡처의 수신과 목적지 처리 결과도 구분합니다. 프레임·상위 데이터·패딩·FCS·MTU의 정의를 연결해서 읽도록 했습니다.

원본 PCAP이 제공되지 않아 실제 명령 실행과 출력·회선 결과를 꾸며내지 않았습니다. 문서용 IPv4 주소와 RFC 9542의 문서용 MAC 주소를 사용한 자체 헤더 예시입니다. 전체 패킷이 아니라 앞부분만 제시합니다. 이번 범위에는 별도 워크북 연습 안내가 없어 자체 복습 8문항과 본문 해설을 구성했습니다.

검증한 계산은 다음과 같습니다.

- 6+6+2=14, 64-14-4=46, 46-28=18, 14+28+18+4=64.
- 14+1500+4=1518, FCS가 없으면 최소60·최대1514바이트인 기본 예시.
- 단일 태그로 14+4=18, 18+1500+4=1522, FCS 미제공 캡처의 최대1518.
- 0x05dc=1500, 0x0600=1536. 1501~1535를 일반 길이로 확정하지 않음.
- TCI 3+1+12=16비트, 2의12승=4096조합. 모든 조합이 일반 VLAN 번호로 사용 가능하다고 쓰지 않음.
- TCI 0x002a의 PCP0·DEI0·VID42, 태그 뒤 안쪽 유형16~17·IPv4 시작18. 태그 없는 IPv4 시작14와 차이4.
- 64×8=512비트. 10 Mb/s의 단순 송신 시간은 51.2마이크로초. 이 숫자로 실제 허용 케이블 길이를 확정하지 않음.

## 현재성 확인

Wireshark의 Ethernet·MTU·VLAN 수집 문서, tcpdump 공식 매뉴얼, IEEE 802.1 공개 프로토콜 식별 기술 자료, RFC 4861·9542, Cisco의 duplex·802.1Q·VTP 문서, Juniper VLAN 필드 정의 검색 결과, Suricata 8.0.1 공식 수집 문서, NIST WLAN 지침을 조회했습니다. 본문에 근거와 확인 날짜를 제공합니다. Juniper 전체 PDF는 조회 도구의 크기 제한이 있었지만 공식 검색 결과의 필드 정의를 확인했습니다. IEEE 기술 자료는 2020년 초안임을 명시하고 최종 표준 그 자체라고 쓰지 않았습니다.

기초 헤더·주소·패딩·프레임 길이는 유효합니다. 다음은 보완했습니다.

- 무선·단말을 보안상 무의미한 범위로 제외하지 않으며 학습 초점과 중요성을 구분.
- 현대 802.3 전체를 항상 LLC/SNAP만 쓰는 형식으로 일반화하지 않음.
- Type/Length의 두 경계, FCS 제공 여부의 조건, CRC와 인증·악성 판정의 차이.
- 반이중 기가비트의 표준 역사와 현대 제품의 전이중 지원을 구분. late collision과 IP/TCP의 역할을 구분.
- 역사적 CFI와 현재 DEI, 태깅과 VTP 구성 관리의 구분.
- 태그 제거가 탐지기의 지원 문제를 줄일 수 있다는 이유와 VLAN 문맥·흐름 구분을 잃을 가능성을 함께 설명. 실제 설정 변경은 하지 않음.
- 태그가 보이지 않는 캡처와 VLAN 부재를 같은 것으로 취급하지 않음.

## 게시 전 검증과 진행

홈페이지와 노트 9개, 로컬 링크·자산 440개, 새 노트 14절·참고문헌 13개·복습 8문항, 두 SVG와 표를 검사했습니다. 중복 ID·누락 앵커·없는 내부 대상이 없으며 길이·비트·태그 오프셋 계산과 순차 상태가 일치합니다. 기존 본문과 생성 스크립트의 내용은 유지하고 탐색을 재생성합니다.

기존 폰트·어두운 배경·민트 강조 및 반응형 스타일을 유지합니다. 미리보기 인프라 제한으로 실제 브라우저 시각 검증은 수행하지 못했습니다. 구조 검사를 시각 검증으로 보고하지 않습니다.

완료 범위는 인쇄76쪽까지이며 다음은 10강 인쇄77쪽부터입니다. 전체16회차·최종167쪽 범위는 유지하며 상태는 진행 중입니다.
