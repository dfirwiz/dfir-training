## 기존 설명과 이번 보강

기존11절·표7개·SVG1개·복습6문답·실습 연계·출처13개를 보존했습니다. 문단·표 셀·목록·코드·그림 설명의 기존 문자열 보존을 검사했으며 공식 자료 확인일만 갱신했습니다. 새 조건 비교표1개와 프록시 연결/센서 관측SVG1개를 추가해 총표8개·SVG2개입니다. 복습10개를 보강해16문답과 즉시 읽는 해설을 제공합니다. 기존 앵커·코스명·URL·번호·스타일을 유지합니다.

기존 원문 대응 기록과 워크북 보충 검토 기록을 확인했습니다. 이전5강 기록의 워크북/PCAP 미확보 표현은 당시 기록으로 구별했습니다. 현재는 첫째 날 워크북 학습 목표와 PCAP6개/621기록의 기존 오프라인 대조 기록이 있으며 이번 새 검토에서 “실습자료 미제공”이라고 단정하지 않습니다. 이번 실행에서 원본 워크북·PCAP을 다시 분석하거나 tcpdump/TShark/Suricata/Wireshark를 실행하지 않았습니다. 기존 검증과 이번 가상 구간 계산은 별도입니다.

## 예제 전제·산술 검증

- 연결 설정 이후 같은 방향의 데이터 구간이라는 기존 전제를 유지했습니다. 시퀀스 번호를 패킷 일련번호와 구별하고 SYN·FIN 및 양방향 번호 공간 주의를 보존했습니다.
- 아직 응용으로 전달되지 않은 데이터라는 전제를 설명하기 위해 앞쪽998·999를 기다리는 버퍼 예시를 추가했습니다.1000~1005의 결과를 완전한 연결 전체와 혼동하지 않습니다.
- 먼저 온1000~1003 ABCD와 나중1002~1005 XYEF:겹침2,서로 다른 위치6,가상 먼저값ABCDEF/나중값ABXYEF를 사전 기반 독립 계산으로 검증.
- 두 번째를CDEF로 변경:동일 바이트 중복,두 가상 정책ABCDEF.
- 시작1004로 변경:겹침 없이8위치,ABCDXYEF.

- 104−6×4−5×4=60바이트,40<24+20 및0x10=16=00010000을 검산.
- 실제 OS·네트워크·공격 재현으로 표현하지 않습니다. 센서 해석 가능성·실제 수신 결과·응용 영향·의도를 구분합니다.

## 현재성·공식 출처

2026년11월2일 본문 출처13개를 실제 열었습니다. RFC Editor 문서 관계와 정오표 상태, RFC9293/768/791/792/8200/9000/2119/8174/9413,Suricata8.0.1 host-os-policy,Wireshark offloading을 확인했습니다. 요구사항 대문자 규약과 대상 정책은 공식 출처 검색 및 해당8.0.1 문서 절로 재확인했습니다.

TCP9293의2022년 대체와 IPv68200의2017년 대체,QUIC9000의2021년 발행과 현재 확인일을 구별합니다. RFC9413은Informational로 개별 프로토콜 의무를 대체하지 않는다는 설명을 유지했습니다. Suricata8.0.1 링크를 최신판 전체로 소개하거나 그 정책을 실제 배포했다고 주장하지 않습니다. Reported 정오표를 확정 수정으로 취급하지 않고 SHOULD와MAY의 의미를 보완했습니다.
