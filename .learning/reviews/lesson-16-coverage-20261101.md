## 현재성 확인과 보완

- IPv4의 길이·위치·재조립 원리는 유효합니다. RFC1122의 역사적 중첩 논의를 현재의 모든 구현에 대한 동일 채택 의무로 일반화하지 않았습니다. 특정 Windows의 현재 동작이나 RFC위반을 검증했다고 하지 않습니다.
- RFC8200 §4.5의 중첩 폐기와 정확한 중복본만 제거할 수 있는 선택을 구별했습니다. 중첩/동일 데이터 중복/내용 충돌을 같은 말로 쓰지 않습니다.
- Suricata 공식8.0.2 문서와 현재9.0.0-dev 문서의 host-os-policy·defrag를 대조했습니다. 개발 문서를 운영 안정 버전으로 소개하지 않고 실제 버전·시간 제한·메모리·조각 추적 한도와 정책을 확인하도록 설명했습니다. 운영 설정 변경은 수행하지 않았습니다.
- tcpdump 공식 매뉴얼과 IPv4 소스에서 -A 범위, 옵션, Offset의8배 환산, 첫/뒤 조각 처리 경로를 확인했습니다. ASCII에서 단어만 편집한 표시를 실제 덤프로 오인시키지 않습니다.
- Wireshark 현재 공식 IPv4 해석 소스를 읽고 확인한 리비전의 기본 ip_defragment=true, 재조립 처리와 상위 해석 분기를 확인했습니다. 해당 리비전의 파일을 다시 읽어 조회한 원문과 동일함을 비교했습니다. 본문 근거 링크는 확인한 리비전에 고정했습니다.
- 과거 Wiki의 재조립 기본 비활성 설명을 현재 고정값으로 옮기지 않습니다. 실제 프로파일은 달라질 수 있습니다. 상위 해석이 재조립 완료 프레임에 나타나는 동작을 오류나 과도한 해석이라고 단정하지 않습니다.
- Wireshark 공식 필드의 ip.fragment.overlap/conflict·ip.reassembled_in/length/data와 libpcap 포트 필터의 IPv4 첫 조각 조건을 확인했습니다. 원시 선택과 재조립 이후 표시를 구별하고, 누락 바이트를 필터로 복원한다고 하지 않습니다.
- RFC1858·RFC3128로 상위 TCP 헤더 전체가 항상 첫 IPv4 조각에 있다는 일반화를 보완했습니다. 헤더가 각 조각에 새로 붙지 않는 원칙과 첫 조각에 전부 들어 있다는 가정을 구별했습니다.
- IP 체크섬은 헤더만 검사하며 서로 다른 헤더의 값이 우연히 같을 수 있습니다. ICMP는 전체 메시지, TCP·UDP는 의사 헤더를 포함한 해당 전체 단위를 사용합니다. IPv4 UDP0의 미사용 의미, 체크섬≠인증, 호스트 오프로딩의 표시 한계도 공식 문서와 대조했습니다.
- 현재 TCP 표준은 RFC9293을 인용했습니다. IP 재조립·TLS 복호화·대상의 응용 처리를 구별하고 현대에도 패킷 분석의 역할과 암호화 가시성의 한계를 연결했습니다. 근거18항과 확인일을 본문에 붙였습니다.

## 자체 계산과 검증

가상 통신 주소는 문서용 범위입니다. 아래 결과는 직접 정의한 메모리 배열의 검산이며 PCAP·회선·운영체제 실행 결과가 아닙니다.
