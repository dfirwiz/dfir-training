## 정의·예제와 한계

- 디섹터, 인터페이스, 표시 필터, 수집 필터, 세 패널과 오프셋, 데이터 소스, 스트림·대화·객체의 역할을 문맥에서 설명했습니다.
- tcpdump -r, -w와 host 조건, Wireshark -r 및 위치 파일 인자를 설명했습니다. &는 셸 표기이며 GUI·수집 옵션이 아님을 구분했습니다. 명령을 실제 실행한 것으로 표시하지 않았습니다.
- TCP 재조립과 UDP 대화 표시를 같은 전달 보장으로 해석하지 않습니다. 필터로 맥락을 잃을 수 있어 원본 유지와 추출 조건 기록을 설명했습니다.
- 자체 구성 예제는 VLAN 없는 Ethernet II / 옵션 없는 IPv4 / ICMP를 가정합니다. MAC 주소는 설명용으로 구성했고 IP는 문서용 주소입니다. 바이트는 전체 프레임이 아닌 앞부분만 제시했습니다.
- 6+6+2=14, IP 시작 14, Total Length 위치 14+2=16, 0x003c=60, IHL 5×4=20, ICMP 시작 14+20=34, IP 데이터 60-20=40, 프레임 14+60=74바이트=592비트, ICMP Echo 데이터 40-8=32를 검증했습니다.
- 25/1000×100=2.5%는 가상 필터 표시 비율이며 전체 네트워크나 공격 비율이 아닙니다.
- 0x45는 모든 IPv4 첫 바이트로 고정되지 않고 오프셋 14도 모든 링크 형식에 적용되지 않음을 명시했습니다.
- 암호화와 데이터 누락, 생성된 분석 정보와 실제 바이트를 구분하고, 패킷으로 확인한 사실·확정할 수 없는 결과·추가 로그를 분리했습니다.

## 최신 보충과 근거

공식 Wireshark 사용자 가이드의 메인 화면·세 패널·상태 표시줄·표시 필터·대화 통계·Follow·Export Objects, 공식 실행 매뉴얼과 HTTP 필드 참조, TLS 문서 및 tcpdump 공식 매뉴얼 소스를 현재 조회했습니다. 링크와 확인 날짜는 본문에 제공합니다. UI의 특정 최신 릴리스 번호를 추측하지 않았고, 설치 환경별 차이를 설명했습니다.

바이트 패널의 재조립·복호화 데이터 탭, 상세 패널의 생성 정보, 표시 필터와 수집 필터의 차이를 보완했습니다. 기본적인 세 패널 탐색과 도구 조합은 현재도 유효한 원칙입니다. 객체 추출과 Follow가 누락 자료나 암호화를 자동 해결한다고 쓰지 않았습니다.

## 게시 전 검증

홈페이지와 노트 6개, 로컬 링크·자산 276개, 새 본문의 12절·13개 참고문헌을 구조 검사했습니다. 중복 ID·누락 앵커·없는 링크 대상이 없고 표·SVG의 구조와 접근성 제목, 표시 필터와 명령의 표기, 계산 및 순차 상태가 일치함을 확인했습니다. 원문 그림은 자체 설명 도식으로 대체했고 공개 파일에서 원문 식별자·화면·개인정보를 배제했습니다.

기존 폰트와 어두운 배경·민트 강조 및 표·그림의 반응형 스타일을 유지합니다. 미리보기 인프라의 기존 제한으로 브라우저의 실제 화면 시각 검증은 수행하지 못했습니다. 구조 검사를 시각 검증 완료라고 보고하지 않습니다.
