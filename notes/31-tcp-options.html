학습 범위와 예제

둘째 날 9강 · 교재 인쇄 98~106쪽의 학습 주제를 자체 예제와 해설로 풀었습니다. 아래 주소·숫자·흐름은 별도 표시가 없으면 가상 학습 예시입니다. 명령은 분석 절차이며 실제 실행 출력으로 제시하지 않습니다.

1. 같은 TCP라도 조건을 맞추는 방법이 다릅니다

큰 물건을 배달하기 전에 문 크기와 보관 공간을 확인하면 효율적이겠지요. TCP 옵션도 연결 양끝이 추가 능력과 조건을 알리는 데 사용됩니다. TCP 기본 헤더 뒤에 붙으며 전체 헤더 길이는 Data Offset으로 확인합니다. 옵션의 종류·길이·값을 읽고 NOP와 EOL 같은 특수 옵션을 구별합니다.

헤더 전체는 4바이트 단위에 맞춰집니다. 각 옵션이 모두 개별적으로 4바이트 길이여야 한다는 뜻은 아닙니다. NOP를 포함한 옵션 순서가 구현의 단서가 될 수 있지만, 특정 배열 하나로 운영체제와 버전을 확정할 수는 없습니다.

2. MSS는 내가 받을 수 있는 TCP 데이터 크기를 알립니다

MSS는 한 TCP 세그먼트의 데이터 크기에 관한 값입니다. A가 SYN에서 광고한 MSS는 B가 A에게 보낼 때 참고할 수신 한도입니다. B도 자기 값을 따로 광고합니다. 교재의 “둘 중 작은 값을 양방향에 쓴다”는 식의 단순화 대신 방향별 광고로 이해해야 합니다.

기본 IPv4 헤더 20바이트와 TCP 헤더 20바이트, 경로 MTU 1500이라는 단순 조건에서는 1460바이트 데이터 예산을 생각할 수 있습니다. 실제 IP·TCP 옵션과 터널이 있으면 송신 시 데이터에 쓸 수 있는 공간은 더 줄 수 있습니다. 광고된 MSS와 모든 패킷의 실제 페이로드 길이가 같아야 하는 것은 아닙니다.

MSS는 전체 Ethernet 프레임 길이도 아니고 수신 버퍼 전체 크기도 아닙니다. 큰 파일을 보낼 때는 많은 세그먼트로 나누고, 재전송도 따로 관리합니다. MTU·MSS·수신 윈도를 구별하면 “크다”는 말을 서로 다른 단위로 혼용하지 않게 됩니다.

3. 윈도 스케일 값 7은 일곱 배가 아닙니다

윈도 스케일은 왼쪽으로 몇 비트 이동할지 알리는 값입니다. 스케일이 7이면 2의 7승, 즉 128배입니다. 원시 윈도 값이 1000이고 그 방향의 광고에 적용할 스케일이 7이라면 계산값은 128000바이트입니다. 이 옵션도 양방향을 따로 추적합니다.

스케일은 SYN 교환에서 협상하며 SYN 자체의 윈도 필드에는 스케일을 적용하지 않습니다. 연결 중간부터 캡처하면 협상 값을 몰라 계산이 불확실할 수 있습니다. Wireshark의 원시 윈도와 계산된 윈도를 구별하고 추정값을 확정값으로 보고하지 않습니다.

기다리는 동안 선로를 채우려면 왕복 시간도 고려해야 합니다. 100Mbps에 RTT 40ms라면 단순 대역폭·지연 곱은 100000000×0.04/8=500000바이트입니다. 윈도/RTT는 윈도 제한을 이해하는 근사이며 실제 속도 보증은 아닙니다. 손실·혼잡·응용·장치 성능을 함께 봅니다.

가상 계산
원시 윈도 1000, 협상 스케일 7
1000 × 2^7 = 128000바이트

100Mbps × RTT 0.04초 ÷ 8 = 500000바이트

4. SACK은 뒤쪽에 도착한 구간도 알려줍니다

받는 쪽이 1001~1500을 기다리는데 1501~2000이 먼저 왔다고 합시다. 누적 ACK는 1001에 머물 수 있습니다. SACK은 뒤쪽의 어느 구간을 받았는지 추가로 알려 손실 복구를 돕습니다. SACK 블록의 왼쪽 경계는 포함하고 오른쪽 경계는 포함하지 않는 방식으로 읽습니다.

예를 들어 [1501,2001)은 500바이트 구간입니다. SYN의 SACK Permitted는 기능을 허용한다는 뜻이며 실제 수신 블록이 아닙니다. SACK 정보를 받았다고 응용이 그 구간을 이미 처리했다고 해석하지도 않습니다. 여전히 중간 공백과 누적 ACK를 함께 봐야 합니다.

5. Timestamp와 Fast Open은 무엇을 바꾸나요?

TCP Timestamp는 TSval과 TSecr를 통해 RTT 측정과 오래된 세그먼트 구별 같은 기능을 돕습니다. 보통의 날짜·시각 문자열이 아니며 값의 증가 속도를 모든 호스트에서 같다고 가정할 수 없습니다. 이 값 하나로 정확한 부팅 시각이나 운영체제를 확정하지 마세요.

Fast Open은 지원되는 조건에서 초기 SYN 등에 데이터를 실어 연결 초기에 데이터를 전달할 수 있게 합니다. 그러므로 SYN에 데이터가 있다는 이유 하나로 악성이라고 단정하지 않습니다. 옵션과 쿠키, 재전송·재생 가능성 및 응용의 적합성을 함께 살핍니다. 모든 서버가 이를 수용한다고 가정할 수도 없습니다.

OS 지문은 옵션 순서·MSS·윈도·TTL 같은 여러 단서가 맞는지 보는 추정입니다. 프록시나 부하분산 장비가 종단 대신 응답할 수 있고 설정도 달라집니다. 보고할 때는 “해당 구현과 일치하는 단서”와 실제 자산 정보의 확인을 나눕니다.

질문 2. 스케일 4, 원시 윈도 2000의 계산값은?

질문 3. SACK [3001,3501)은 몇 바이트인가요?

Fast Open 등과 수신 구현을 검토합니다. 플래그 하나만으로 악성을 확정하지 않습니다.
